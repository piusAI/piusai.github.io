### 002 AABB vs OBB ( 게임 엔진 및 충돌 처리)
게임 엔진에서는 **Collision Detection**의 최적화를 위한 가장 기초적인 판단 기준으로 사용 된다.

###### 1. AABB (Axis-Aligned Bounding Box)
- 장점 : 충돌 연산 **매우 빠르고 간편**. 두 (AABB의 min/max 좌표값만 검사)
- 단점 : Object가 위에 본바와 같이 회전했을때, 불필요한 빈 공간이 커져서 **충돌 오차가 커질 수 있음**
- 용도 : Broad-Phase 충돌 검사(대략적인 1차.스크리닝), Static Mesh, Quad-Tree /Octree 공간 분할.

####### C++ AABB Collision Detection 예시

```cpp

//AABB

#include <iostream>
using namespace std;

struct Vector2{ float x, y ;};
struct AABB {
	Vector2 min; // 좌하단 점
	Vector2 max; // 우상단 점
	
	
	bool intersect(const AABB& other) const {
	return (this->min.x <= other.max.x && this->max.x >= other.min.x) &&
			(this->min.y <= other.min.y && this->max.y>= other.min.y);
	}
};

int main()
	{
	AABB box1 = {{0.0f, 0.0f}, {5.0f, 5.0f}};
	AABB box2 = {{-4.0f, -4.0f}, {5.0f, 5.0f}};
	AABB box3 = {{3.0f, 3.0f}, {8.0f, 8.0f}};
	
	cout<<"box1, box2 colision detect? : " << boolalpha<< box1.intersect(box2)<<endl;	
	
	cout<<"box2, box3 colision detect? : " << boolalpha<< box2.intersect(box3)<<endl;
	
	}
```

###### 2. OBB (Orient Bounding Box)
- 장점 : 회전된 물체에도 형태 타이트하게 맞물려 **충돌 판정 정확**
- 단점 : SAT(분리축 정리, Seprating Axis Theroem)알고리즘을 써야해 AABB에 비해 *연산 비용* 높다
- 용도 : Narrow-Phase 충돌 검사(정밀한 2차검사), 회전하는 object, 캐릭터 세부 Hitbox

|             | **AABB (Axis-Aligned Bounding Box)**           | **OBB (Oriented Bounding Box)**                |
| ----------- | ---------------------------------------------- | ---------------------------------------------- |
| **특징**      | **월드 축(World Axis)에 고정**된 바운딩 박스               | **오브젝트의 회전(Orientation)을 반영**하는 바운딩 박스         |
| **차이**      | 오브젝트를 회전시켜도 BBox는 항상 **월드** X, Y, Z축과 평행하게 늘어남 | 오브젝트가 회전하면 BBox도 **함께 회전**함                    |
| **Data 형태** | Min, Max 좌표만으로 표현 가능 (`Vector3 min, max`)      | Center, Extents, Rotation Matrix/Quaternion 필요 |

### 💡 요약
- **AABB**: "연산은 빠르지만, 회전하면 박스가 커진다."
- **OBB**: "회전해도 딱 맞아서 정밀하지만, 연산이 조금 더 비싸다."
