## 1. LEB 이해 (A 영역)

### 1.1 한 장 요약

- 지형은 한 변이 `L`인 정사각형이고, 정수 격자 `0..G` (`G = 2^K`) 위에 놓입니다.
- 삼각형은 **정수 꼭짓점 3개** `V[0], V[1], V[2]`입니다. `V[1]`이 직각 꼭짓점이고 `V[0]–V[2]`가 빗변입니다.
- 분할은 하나뿐입니다. **빗변의 중점 M을 직각 꼭짓점과 이어 둘로 가른다.**
- 가른 결과도 이등변 직각삼각형이므로 같은 규칙을 계속 적용할 수 있습니다.
- 한 곳만 쪼개면 이웃과 틈이 생기므로, **빗변 건너편 이웃도 함께 쪼갭니다.** (conforming)

```cpp
// 구조체 (FIZLEB_v08_1_1.h)
struct FIZLebTriangle { uint32 NodeID; FIntPoint V[3]; int32 Depth; bool bAlive; };
//  V[0]──빗변──V[2],  V[1] = 직각 꼭짓점,  Depth = 분할 횟수,  bAlive = 현재 리프인가
```

### 1.2 분할 규칙 (코드 `SplitOne`)

```
M = (V0 + V2) / 2                  // 정수 나눗셈 (아래 1.5 참고)
자식0 = (V1, M, V0)
자식1 = (V2, M, V1)
```

아래는 1.3의 base0 = V0(0,0), V1(2,0), V2(2,2) 를 쪼갠 모습입니다.

```
                  V2 (2,2)
                 ╱│
               ╱  │
        M(1,1)╱ 자식1: (V2, M, V1)
            ╱  ╲  │
          ╱ 자식0 ╲│
      V0 ──────────V1 (2,0)          자식0: (V1, M, V0)
   (0,0)                              M 과 V1 을 이은 선이 새 경계
```

두 자식 모두 직각 꼭짓점이 M이고, 자식0의 새 빗변은 V1–V0, 자식1의 새 빗변은 V2–V1입니다.

핵심 성질 두 가지만 기억하면 됩니다.

1. 자식의 **새 빗변은 부모의 직각변**이고, 직각 꼭짓점은 **M**입니다.
2. 분할할 때마다 삼각형 면적이 정확히 절반이 되고, 모양은 **항상 이등변 직각삼각형(서로 닮음)** 입니다. 가늘고 긴 삼각형이 생기지 않습니다.

### 1.3 손으로 따라가 보는 K=1 예제 (G=2)

시작: `Reset()`이 만든 삼각형 2개

|NodeID|V0|V1|V2|
|---|---|---|---|
|2 (base0)|(0,0)|(2,0)|(2,2)|
|3 (base1)|(2,2)|(0,2)|(0,0)|

base0의 빗변은 (0,0)–(2,2)이고 base1의 빗변도 (0,0)–(2,2)입니다. **서로 같은 빗변을 공유하는 diamond 쌍**입니다.

`SplitConforming(base0)`:

1. base0의 빗변 엣지 키로 이웃을 찾으면 base1이 나옵니다.
2. base1의 빗변 키도 같습니다 (`NeighborHypKey == HypKey`). 그래서 **둘 다 분할**합니다.
3. M = (1,1)

|새 NodeID|V0|V1|V2|부모|
|---|---|---|---|---|
|4|(2,0)|(1,1)|(0,0)|base0|
|5|(2,2)|(1,1)|(2,0)|base0|
|6|(0,2)|(1,1)|(2,2)|base1|
|7|(0,0)|(1,1)|(0,2)|base1|

중심 (1,1)을 둘러싼 삼각형 4개(깊이 1)가 되었고 틈이 없습니다. 노드 4의 새 빗변은 (2,0)–(0,0)인데 이는 부모 base0의 직각변이었습니다. ← 성질 1 확인

**만약 이웃을 같이 쪼개지 않았다면?** base0만 쪼개면 (1,1)이 base1에는 없는 꼭짓점이 됩니다. base1은 (0,0)–(2,2) 한 변을 그대로 쓰는데 base0 쪽에는 그 변 위에 (1,1)이 있으니, 높이를 변위(displacement)시키면 (1,1)만 움직이고 base1은 안 움직여 **균열(crack)** 이 생깁니다. 이것이 T-junction이고, conforming 분할은 이걸 막습니다.

### 1.4 `SplitConforming`이 하는 일 (재귀)

```
Split(T):
  T' = 빗변 건너편 이웃
  if T' 없음(경계)           → T만 분할
  if hyp(T') == hyp(T)       → T, T' 둘 다 분할 (diamond)
  else                       → Split(T') 먼저 (T'가 한 단계 더 거칠다)  → 다시 T로 돌아와 반복
```

- 빗변 건너편 이웃은 **같은 깊이(diamond)이거나 한 단계 더 거친 삼각형**입니다. 거친 쪽을 먼저 쪼개 같은 깊이로 맞추면 diamond가 됩니다.
- 재귀 체인은 깊이가 계속 줄어드므로 **최대 `d(T)` 단계**에서 끝납니다. 그래서 한 번의 분할은 `O(depth)`번의 추가 분할을 부를 수 있고, 이것이 `MaxTriangles`를 약간 넘길 수 있는 이유입니다.
- 코드의 `SafetyCounter < 1000`은 무한 루프 방지용 안전장치입니다.

### 1.5 왜 정수 격자인가 (양자화 ①)

- 꼭짓점이 정수이므로 **"같은 점인가"가 부동소수점 오차 없이 정확히 비교**됩니다. 이웃 찾기, T-junction 판정이 모두 `==` 비교로 끝납니다.
- 중점 `(V0+V2)/2`도 정수 나눗셈이 **정확히 나누어떨어지는 범위**에서만 쓰입니다. 격자 크기 `G=2^K`는 이 조건이 깨지기 전까지 K번 반으로 쪼갤 수 있게 하려고 2의 거듭제곱입니다.
- 정수 좌표 → 월드(로컬) 좌표는 마지막에 한 번만 변환합니다. $$\mathbf x(\mathbf g)=\left(\mathbf g-\tfrac G2\right)s,\qquad s=\tfrac LG$$ CPU 거리 계산(`ComputeDistanceToTriangle2D`)과 셰이더가 같은 식을 씁니다. **플레이어 위치는 양자화하지 않습니다.** float 그대로 이 변환된 삼각형과 비교합니다.

### 1.6 비트 패킹은 무엇인가 (양자화 ②, 구현 디테일)

목적은 하나입니다. **"이 엣지를 쓰는 삼각형 2개"를 `O(1)`로 찾는 사전**을 만드는 것입니다. 파이썬으로 쓰면

```python
edges = { frozenset({p1, p2}): [tri_a, tri_b] }
```

와 같습니다. 이걸 C++ `TMap`의 키(정수 하나)로 만들려고 점을 정수로 압축합니다.

```cpp
PackPoint(P)    = (P.X << 16) | P.Y            // 점 하나 → uint32 (X는 위 16비트, Y는 아래 16비트)
MakeEdgeKey(P1,P2):  A=Pack(P1), B=Pack(P2);  if (A>B) swap;  return (A << 32) | B   // 엣지 → uint64
```

- 숫자 예: P=(3,5) → `3·65536 + 5 = 196613`. P=(7,5) → `458757`. 엣지 (3,5)–(7,5)의 키는 `(196613 << 32) | 458757`이고, 순서를 뒤집어도 `swap` 덕분에 **같은 키**가 됩니다. (방향 없는 엣지)
- `& 0xFFFF`는 음수/오버플로 방어용 마스크입니다.
- 좌표가 16비트(65535) 안에 들어와야 하므로 `G ≤ 4096`, 즉 K ≤ 12까지 안전합니다. 이 코드의 `K = clamp(..., 1, 12)`와 일치합니다.
- `FEdgeUsers { A, B }`는 그 엣지를 쓰는 삼각형 인덱스 최대 2개입니다.

**GT/RenderThread 코드와 달라 보이는 이유**: `FIZLEB`은 스레드와 무관한 순수 CPU 자료구조입니다. 렌더 스레드의 `Refine` 안에서 호출될 뿐이고, 시프트와 마스크는 위 해시 키를 만드는 용도로만 쓰입니다.

### 1.7 NodeID (논문에서는 거의 안 씀)

- 힙 번호 매기기 : 루트 1, 노드 `k`의 자식은 `2k`, `2k+1`. 베이스 삼각형은 2, 3.
- NodeID의 비트열이 곧 "루트에서 왼쪽/오른쪽으로 내려온 경로"입니다. 그래서 NodeID만 알면 꼭짓점을 비트 연산으로 복원할 수 있습니다. (`DecodeTriangleVertices`)
- **Final 경로에서는 쓰지 않습니다.** `Triangles` 배열이 꼭짓점을 직접 들고 있어서 복원이 필요 없습니다. 쓰이는 곳은 ① 토폴로지 변경 감지(`ScratchLeafNodeIDs`를 이전 값과 비교) ② 향후 GPU 확장 (CBT 합 트리)입니다.
- 논문에서는 "NodeID로 토폴로지가 유일하게 식별되어 이전 프레임과 비교할 수 있다" 정도면 충분합니다.

### 1.8 양자화는 세 종류이고, 서로 무관합니다

|이름|무엇을|식|용도|논문|
|---|---|---|---|---|
|정수 격자|삼각형 꼭짓점|`g ∈ {0..G}²`|정확한 이웃/균열 판정|필수|
|셀 키|플레이어/footprint 위치|`floor(x_local / ℓ)`|재방문 판정, footprint 중복 방지 (ℓ=100cm)|필수|
|엣지 키|격자 엣지|`(Pack(A)<<32)|Pack(B)`|`TMap` 해시|

세 개를 섞어서 생각하면 혼란스럽습니다. 격자는 **지오메트리**, 셀 키는 **상호작용 이력**, 엣지 키는 **해시 구현**입니다.

### 1.9 이해 확인 (스스로 점검)

1. 위 K=1 예제에서 노드 4를 한 번 더 쪼개면 M은? 이웃은 있나? (답: M=(1,0), 빗변 (2,0)–(0,0) 건너편은 지형 밖이라 이웃 없음 → 단독 분할)
2. 노드 5의 빗변은 (2,2)–(2,0)이고 노드 6의 빗변은 (0,2)–(2,2)입니다. 둘이 맞닿은 엣지 (1,1)–(2,2)는 양쪽 모두에게 빗변이 아닙니다. 노드 5만 쪼개면 이 엣지 위에 새 꼭짓점이 생길까요? (답: 아니오. M=(2,1)은 5의 빗변 위(지형 경계)에 생기므로 (1,1)–(2,2)는 그대로라서 균열이 없습니다. 균열은 **빗변 위에 M이 생기는데 건너편이 그 빗변을 쪼개지 않을 때**만 생깁니다)
3. 깊이가 3 차이 나는 이웃이 생길 수 있는가? (아니오, conforming에서는 최대 1단계 차이)

### 2.1 [Eq.1] 이등변 직각삼각형 이분할 (LEB)

삼각형 $T=(v_0,v_1,v_2)$ ($v_1$ 직각 꼭짓점, $v_0v_2$ 빗변), 중점 $m=\tfrac{v_0+v_2}{2}$:

$$\mathrm{Bisect}(T)={,T_L,,T_R,},\qquad T_L=(v_1,,m,,v_0),\quad T_R=(v_2,,m,,v_1)$$

초기 사각형 $[0,G]^2$는 대각선으로 갈라진 두 삼각형 $T^0_0=(\mathbf 0,(G,0),(G,G))$, $T^0_1=((G,G),(0,G),\mathbf 0)$로 시작한다. 정점은 $\mathbf g\in{0,\dots,G}^2$이고 로컬 좌표는 $\mathbf x(\mathbf g)=(\mathbf g-\tfrac G2),s$.

**성질 (논문에 한 문장으로)**: 모든 삼각형은 서로 닮은 이등변 직각삼각형이고 (shape-regular), 깊이 $d$에서

$$N(d)=2^{,d+1},\qquad A(d)=\frac{L^2}{2^{,d+1}},\qquad \ell_{leg}(d)=L,2^{-d/2}$$

구현은 $d\le d_{\max}=2K-1$로 제한한다. 이때 가장 작은 삼각형의 직각변은 $\sqrt2,s$, 개수는 $2^{2K}=G^2$이다. (참고: 정수 중점은 깊이 $2K$ 삼각형 생성까지 가능하므로, 한 단계 더 쪼개면 $2G^2$개의 단위 격자 삼각형이 된다. 현재 구현은 의도적으로 한 단계 앞에서 막는다.)

### 2.2 [Eq.2] Conforming 분할 연산자

$\mathcal N(T)$를 $T$의 빗변 건너편 이웃이라 하자.

$$\mathrm{Split}(T)=\begin{cases}\mathrm{Bisect}(T) & \mathcal N(T)=\varnothing\ \mathrm{Bisect}(T)\ \cup\ \mathrm{Bisect}(\mathcal N(T)) & \mathrm{hyp}(\mathcal N(T))=\mathrm{hyp}(T)\ \mathrm{Split}(\mathcal N(T)),\ \text{then }\mathrm{Split}(T) & \text{otherwise}\end{cases}$$

**명제.** conforming 메시에서 $\mathcal N(T)$의 깊이는 $d(T)$ 또는 $d(T)-1$이다. 따라서 세 번째 경우의 재귀는 깊이가 엄격히 감소하여 최대 $d(T)$단계 안에 종료하고, 결과 메시에는 T-junction이 없다. 한 번의 `Split`이 만드는 추가 분할은 $O(d_{\max})$이다.

(이 명제는 LEB 문헌의 표준 결과입니다. 논문에서는 문헌을 인용하고, 직접 증명하지 않고 "구현에서 T-junction 개수 0을 검증했다"고 쓰는 것을 권합니다. 현재 `v08_1_1`에는 `ValidateTJunctions`가 없어서 v05의 검증 함수를 옮겨서 돌려야 합니다.)

### 2.3 [Eq.3] 점-삼각형 거리

$$d(\mathbf q,T)=\begin{cases}0 & \mathbf q\in T\ \min\limits_{(u,w)\in{(a,b),(b,c),(c,a)}}\ |\mathbf q-\pi_{uw}(\mathbf q)|& \text{otherwise}\end{cases}$$

$$\pi_{uw}(\mathbf q)=u+\tau,(w-u),\qquad \tau=\operatorname{clamp}!\left(\frac{(\mathbf q-u)\cdot(w-u)}{|w-u|^2},,0,,1\right)$$

AABB 거리와 달리 **등거리선이 원**이 되어 상호작용 영역이 박스/대각선 편향 없이 원형으로 나온다. (정성적 비교용 그림 추천: AABB vs 정확 거리의 depth 컬러 맵)

### 2.4 [Eq.4] 거리 → 연속 목표 깊이

$$d^{*}(r)=\begin{cases}0 & r\ge D_{hi}\ d_{\max} & r\le D_{lo}\ d_{\max}\cdot S!\big(\alpha(r)^{\gamma}\big) & \text{otherwise}\end{cases}\qquad \alpha(r)=\frac{D_{hi}-r}{D_{hi}-D_{lo}},\quad S(x)=x^2(3-2x)$$

$d^*$는 **실수값**이다. 반올림은 [Eq.7]에서 모든 기여를 합친 뒤 한 번만 한다. (중간 반올림으로 생기는 경계 떨림 방지)

### 2.5 [Eq.5] 시간 가중치 (hold → 지수 감쇠)

$$w(t)=\begin{cases}1 & t\le h\ e^{-k(t-h)} & t>h\ \wedge\ e^{-k(t-h)}>w_{\min}\ 0 & \text{otherwise}\end{cases},\qquad t_{exp}=h+\frac{1}{k}\ln\frac1{w_{\min}}$$

기본값 $(h,k,w_{\min})=(2,\mathrm{s},1,0.01)$에서 $t_{exp}\approx6.6$ s.

### 2.6 [Eq.6] 플레이어 + footprint 결합과 목표 깊이

현재 가중치 $w_0=\mathbb 1[\text{접촉 중}\wedge a=1]$ ($a$는 [Eq.9] 재방문 허용 여부), $w_i=w(t-\tau_i)$.

$$\Delta(T)=\max\Big\{\,w_0\,\big[d^{*}(d(\tilde{\mathbf p},T))-d_{\min}\big]_+,\ \max_{i}\,w_i\,\big[d^{*}(d(\mathbf c_i,T))-d_{\min}\big]_+\Big\}$$

$$d_{\text{des}}(T)=\operatorname{clamp}\big(d_{\min}+\operatorname{round}(\Delta(T)),\ d_{\min},\ d_{\max}\big)$$

($[x]_+=\max(x,0)$.) 분할 조건은 $d(T)<d_{\text{des}}(T)$.

기저 깊이는 예산 조건으로 결정한다.

$$d_{\min}=2\hat l-1,\qquad \hat l=\max{,l\le l_{\min}:\ 4^{,l}\le N_{\max},}$$

(구현은 좌변에 계수 2를 곱해 2배 보수적이다. 논문에는 위 식을 쓰되 구현을 수정하거나 각주로 밝힐 것.)

### 2.7 [Eq.7] 우선순위와 예산 제약 정제

$$P(T)=\big(d_{\text{des}}(T)-d(T)\big)\cdot 10^{5}-d(\tilde{\mathbf p},T)$$

$P$ 내림차순으로 분할하며 $N=|\text{leaves}|\ge N_{\max}$에서 종료한다 (탐욕적 예산 배분). $10^5$ 계수는 deficit을 1차 키, 플레이어 거리를 2차 키로 하는 사전식 정렬이다. 예산이 부족해도 **플레이어에 가장 가까운 곳이 먼저 최대 해상도에 도달**한다는 것이 이 설계의 효과이다.

> ⚠ 이 서술은 `HeapPush`의 방향이 의도대로일 때만 맞습니다. 이전 문서의 4.5 H1(UE 기본 min-heap)을 먼저 확인하고 수정한 뒤에 쓰세요.

### 2.8 [Eq.8] footprint stamp 집합 관리

- 추가 : 접촉 중, $a=1$, 셀 $\mathbf z(\mathbf p)\notin\mathcal Z_{\mathcal S}$ 이고 마지막 샘플과 거리 $\ge\sigma=\max(25,0.5,r_c)$이면 $(\mathbf p,t)$ 추가, $|\mathcal S|>F$면 가장 오래된 것 제거. 거리가 $\sigma$ 미만이면 마지막 샘플을 갱신.
- 거리 컬링 : $|\mathbf p_{s,xy}-\mathbf c_{i,xy}|>R_{cull}$ 이면 즉시 제거.
- 만료 : $w(t-\tau_i)=0$ 이면 제거.

Render Target이 플레이어 중심 한 변 $W$의 정사각형이면 정확한 컬링 조건은 $|\mathbf p_{s}-\mathbf c_i|_\infty>W/2$이다. 현재 구현은 유클리드 반경 $R_{cull}$(기본 800cm)이라 $W=1800$이면 내접원(900)보다 약간 작아 보수적이다.

### 2.9 [Eq.9] 재방문 억제

$$\mathbf z(\mathbf p)=\big(\lfloor x_l/\ell\rfloor,\ \lfloor y_l/\ell\rfloor\big),\qquad a=\begin{cases}1 & \mathbf z=\mathbf z_{last}\ \mathbb 1[\mathbf z\notin\mathcal V] & \text{otherwise}\end{cases}\ \ (\text{접촉 중}),\quad a=0\ \ (\text{비접촉})$$

$a=1$이고 $\mathbf z\notin\mathcal V$이면 $\mathcal V\leftarrow\mathcal V\cup{\mathbf z}$ (FIFO, $|\mathcal V|\le M$). 이미 방문한 셀을 다시 밟아도 새 고해상도를 만들지 않는다.

> ⚠ 이전 문서의 4.4 P3 (방문 이력이 footprint 만료와 분리되어 있음)을 정책으로 확정한 뒤에 서술하세요.

### 2.10 [Eq.10] 갱신 게이팅

$$\text{refine}\iff \neg\text{init}\ \vee\ |\Delta\mathbf p_{xy}|\ge\theta\ \vee\ \Delta\text{contact}\ \vee\ \Delta\text{settings}\ \vee\ \Delta|\mathcal S|\ \vee\ \big(|\mathcal S|>0\wedge t-t_{last}\ge 0.25\big)$$

정지 상태에서 호출 빈도의 상한은 $4,\mathrm{Hz}$이다.

### 2.11 [Eq.11] 비교 기준(정적 메시)과 압축률

비교 대상은 **같은 최소 삼각형 크기의 균일 메시**로 잡는 것이 공정하다.

$$N_{static}=N(d_{\max})=2^{,d_{\max}+1},\qquad \rho=\frac{N_{adaptive}}{N_{static}}\ \le\ \frac{N_{\max}}{2^{,d_{\max}+1}}$$

$K=8$이면 $d_{\max}=15$, $N_{static}=65536$, $N_{\max}=8192$일 때
$\rho\le12.5\%$. (단위 격자 $2G^2=131072$ 대비로 쓰려면 "한 레벨 더 세밀한 정적 메시와 비교"라고 명시해야 합니다.)

### 2.12 [Eq.12] 시각적 동등성 조건 (연구 목적 1번)

변위 높이장 $H$가 있을 때, 깊이 $d$ 삼각형에서 구간선형 보간 오차는 삼각형이 닮은꼴(shape-regular)이므로

$$|H-I_dH|_{\infty,T}\ \le\ C,\ell_{leg}(d)^2,|D^2H|_{\infty,T}$$

($C$는 삼각형 모양에만 의존하는 상수.) 허용 오차 $\varepsilon$을 만족하는 깊이는

$$d_\varepsilon(\mathbf x)\ \ge\ 2\log_2!\left(L\sqrt{\frac{C,|D^2H(\mathbf x)|}{\varepsilon}}\right)$$

**AIZ의 설계 조건**: 변위가 존재하는 영역(접촉 반경 $r_c$ + footprint 영향)이 $d(\mathbf x)\ge d_\varepsilon$ 영역 안에 들어가야 한다.

$$D_{lo}\ \ge\ r_c+\sigma\quad(\text{최대 해상도 보장 반경}),\qquad d_{\min}\ \ge\ d_\varepsilon\ \text{(변위가 없는 곳)}$$

기본값은 $D_{lo}=150$, $r_c=100$, $\sigma=50$으로 **경계에서 겨우 만족**합니다. 이것이 맞는지 실험에서 확인하세요. $C$를 구하지 않고 "$O(\ell^2)$"로만 쓰고 실험으로 오차를 측정하는 방식이 안전합니다.

## 3. 의사코드 (논문 Algorithm 박스용)

**Algorithm 1. AIZ-Refine** (`FIZLEB_v08_1_1::Refine`)

```
Input : 예측 위치 p̃, footprint 집합 S, 가중치 w0, 파라미터 (d_min, d_max, N_max, D_lo, D_hi, γ, h, k, w_min)
Output: 리프 삼각형 집합 𝓛

1  𝓛 ← {T0_0, T0_1}
2  for T in BFS(𝓛) with d(T) < d_min and |𝓛| < N_max:          // 균일 선분할
3      Split(T)                                                  // Eq.2
4  Q ← ∅
5  for T in 𝓛 with d(T) < d_max:
6      Δ ← Δ(T)  (Eq.6);  if d_des(T) > d(T):  Q.push(T, P(T))  (Eq.7)
7  while Q ≠ ∅ and |𝓛| < N_max:
8      T ← Q.popMax()
9      if T is dead (already split): continue                    // lazy deletion
10     recompute d_des(T)
11     if d(T) < d_des(T):
12         new ← Split(T)                                        // 이웃 연쇄 분할 포함
13         for U in new with d(U) < d_max:
14             if d_des(U) > d(U): Q.push(U, P(U))
15 return 𝓛
```

**Algorithm 2. 프레임 갱신 (렌더 스레드)** (`RefineAndBuildGPUInput_RenderThread`)

```
1  p_s ← smooth(p)                                  // Eq.(VInterpTo)
2  a ← revisitAllowed(p_s, V)                        // Eq.9
3  update S: add (Eq.8), cull by R_cull, expire by w(t) = 0 (Eq.5)
4  if not refineGate(...) : return                   // Eq.10, 이전 GPU 버퍼 유지
5  𝓛 ← AIZ-Refine(...)                               // Algorithm 1
6  if topology(𝓛) ≠ topology(prev):
7      upload grid coords → Compute Shader (position, index) → pooled buffer
```

## 4. 논문에서 줄이거나 빼도 되는 것

- 비트 패킹, `TMap` 엣지 키, NodeID 디코딩, CBT 합 트리, 셰이더 코드 → 구현 절에서 **한 문단**(예: "엣지는 정수 격자 좌표를 64비트 키로 압축하여 상수 시간에 이웃을 찾는다")
- 시스템 구조 그림(스레드 흐름)은 수식보다 그림 한 장이 더 효과적입니다. 기존 V9Algorithm 다이어그램을 정리해서 쓰세요.
- GPU 부분은 "정점 위치/인덱스 생성만 GPU, 토폴로지는 CPU"라고 **정확히** 쓰세요. (Indirect draw, 계층 컬링, hysteresis, 합 트리 렌더 사용은 주장 금지)

## 5. 이전 문서의 정정

- `AIZ_Final_Algorithm.md` 7.1의 "정수 중점이 보장되는 한계가 $2K-1$"은 **부정확**합니다. 정수 중점은 깊이 $2K-1$ 삼각형을 쪼개 깊이 $2K$ (단위 격자 삼각형)를 만드는 것까지 가능합니다. $2K-1$은 구현이 한 단계 앞에서 막는 **설계상 상한**이고, 이 때문에 SumTree 깊이 off-by-one (이전 4.7 S1)도 같은 원인으로 생깁니다. 상한을 $2K$로 올릴지(해상도 2배, 삼각형 수 2배) 현재대로 둘지는 비교 기준(2.11)과 함께 결정하세요.
- 7.2의 $\rho\le 6.25%$는 $2G^2$ 대비입니다. 이 문서의 [Eq.11]처럼 기준을 명시하세요.
