#### 3.3.1 수 표현
- 2진법 : `0b` (C++14부터 지원)
- 16진법 : `0x`
- 8진법 : `017`. =. 5 ->잘안씀


> 10진수  : 15
> 2진수   : 0b1111  (4비트, 전부 1)
> 16진수  : 0xF     (한 글자)

- 16진수 하나가 정확히 **4bit**(2<sup>4</sup> = 16가지)를 표현할 수있다.
```
0xFFFFFFFF
  ↑↑↑↑↑↑↑↑
  F가 8개 → 8칸

8칸 × 4비트 = 32비트 ✅
```

###### 3.3.1.2 Signed Integer - 부호있는 정수
: 음수는 **2의 보수**로 표기한다.  
(부호 비트만 쓰는 "부호 + 크기" 방식은 +0, -0 두개가 존재)

| 크기    | 바이트 | 비트  | 16진수 칸 수              |
| ----- | --- | --- | --------------------- |
| 8bit  | 1   | 8   | 2칸 (`0xFF`)           |
| 16bit | 2   | 16  | 4칸 (`0xFFFF`)         |
| 32bit | 4   | 32  | **8칸** (`0xFFFFFFFF`) |
| 64bit | 8   | 64  | 16칸                   |

**음수를 표현하는 방법**:
1. 가장 앞 비트를 부호 비트로 활용
2. 2의 보수방법 사용

|             | 부호 + 크기       | 2의 보수                         |
| ----------- | ------------- | ----------------------------- |
| 0의 개수       | 2개 (+0, -0)   | **1개**                        |
| 4비트 범위      | -7 ~ +7 (15개) | **-8 ~ +7 (16개)**             |
| 덧셈          | 부호 따라 별도 처리   | **그냥 더하면 됨**                  |
| 뺄셈          | 별도 회로         | `a - b = a + (-b)`로 덧셈 회로 재사용 |
| 부호 있는/없는 덧셈 | 다른 회로         | **같은 회로**                     |

- 2의 보수는 그 낭비되던 자리를 음수 하나더 (-8) 표현 하는데에 쓰인다.

#### 3.3.1.4 부동소수(float) 표현법  

- 소수점이 이리저리 뛰어다닌다(floating)해서 float 소수 표현법!
<table width="100%" style="table-layout: fixed; border-collapse: collapse; border: none;"> <tr style="border: none;"> <td width="100%" style="text-align: center; border: none; padding: 15px;"> <img src="/assets/postimg/GAE/IEEE_float.png" alt="IEEE-754" style="width: 100%; max-width: 100%; height: auto;"> <br><strong>IEEE-754 저장 방법</strong> </td>  </tr> </table>
- s : 부호비트(1bit), e : 지수(8bit), m : 가수 (23bit)
- 지수는 bias(편향) 127(2<sup>7</sup>-1)을 더해서 저장한다. 
  `실제 지수 = 저장된 e - 127`
  이렇게 하면 부호 비트 없이도 큰 값, 작은 값 모두 표현 가능
- 저장된 e가 0(전부 0)과 255(전부 1)은 특수값(0 /비정규수 / Inf/NaN) 전용.
  그래서 일반(정규) 수의 저장값은 1~254, 실제지수는 -126~ +127.

<table width="100%" style="table-layout: fixed; border-collapse: collapse; border: none;"> <tr style="border: none;"> <td width="100%" style="text-align: center; border: none; padding: 15px;"> <img src="/assets/postimg/GAE/floating.png" alt="floating" style="width: 100%; max-width: 100%; height: auto;"> <br><strong>floating 소수</strong> </td>  </tr> </table>
일단 볼 때마다 이해하는데 항상 헷갈리는데 
- 부호와 지수부는 쉽게 이해할 수있다.
- 가수부 : 소수라서 2<sup>-1</sup>부터 시작하는 표현을 `0b0.101 ~`로 처럼 적는다
  단, 정규화된 수는 맨 앞에 암묵적인 1(hidden bit)가 붙어서 `1.101`형태가 된다.
- 부동 소수점중에서 IEEE-754의 방법이 널리 사용되는 표준이다.

###### 절댓값과 정확도 간의 균형
- 절대값이 작을수록 정확도가 높아짐 - 가수 비트 (23bit)는 고정!
	- 값이 작다면 지수가 작아져서 소수점 아래 더 세밀한 자리까지 표현 가능!
	- 값이 클수록 같은 23bit로 더 넓은 간격을 표현하므로 정밀도 떨어짐
→이를 물리학에서는 **유효 자리수**라고 한다.



**FLT_MAX / FLT_MIN 구하기**:
- `FLT_MAX` : IEEE-754에서의 절댓값 최댓값 
- `FLT_MIN` : IEEE-754에서의 절댓값 최솟값 
- 지수부  2<sup>128</sup> : Nan(`Not-a-Number`)로 차지하고있어서 11111110₂ : 254가 최댓값임
- 지수부 최댓값 : 2<sup>127</sup>
- 가수부 최댓값 : (모두 1로 채움) 거의 2값 **(1.99999988079...)**
- 가수부 최솟값 :  2<sup>-126</sup>  ≈`1.1754944e-38` (그 아래는 비정규수로 약 `1.4e-45`까지 표현)

- IEEE 754 single precision (32비트 float)의 최대 유한 값 (finite maximum)
  지수(biased) 최대 = 254 (즉, 11111110₂) = 254 - 127 = **127**
<table width="50%" style="table-layout: fixed; border-collapse: collapse; border: none;"> <tr style="border: none;"> <td width="100%" style="text-align: center; border: none; padding: 15px;"> <img src="/assets/postimg/GAE/2_128.png" alt="floating" style="width: 100%; max-width: 100%; height: auto;"> <br><strong>FLT_MAX</strong> </td>  </tr> </table>
- **FLT_MAX**  : 2¹²⁷ × (1.99999988079...) ≈ 2¹²⁸ ≈ 3.403 × 10³⁸
- **FLT_MIN** = 2⁻¹²⁶ ≈ 1.175494351 × 10⁻³⁸

`FLT_MAX` : 0x00FFFFFF x 2<sup>127</sup> = 0xFFFFFF00000000000000000000000000
- `FLT_MAX`는 뒤에 26개의 0이 붙어있다. -> 비트 **104(26x4)**칸
- 총 24개의 연속된 이진수(F 하나 : 4개의 이진수 1) 1을 127 비트만큼 shift 한 값이다.

- 작은 수를 `FLT_MAX`에서 뺀다면 여전히 `FLT_MAX`이다
  → 2<sup>104</sup>에 비하면 턱 없이 작은 수를 더하더라도 어차피 티도안나서 작은수는 다 무시된다
- 크기가 1보다 많이 작은 경우 정밀한 값을 표현할 수 있다

- 한 칸의 크기는 지수가 정한다

| 값 근처    | 지수   | 한 칸 간격           |
| ------- | ---- | ---------------- |
| FLT_MAX | +127 | 2¹⁰⁴ (엄청 큼)      |
| 1       | 0    | 2⁻²³ ≈ 0.0000001 |
| 아주 작은 수 | -100 | 2⁻¹²³ (엄청 촘촘)    |

- 가수는 항상 `1.xxxx(23bit)`로 정해두고, 앞에 0이 몇개 붙는지, 움직이는지는 지수가 기억한다!
→ 부동 소수 표현에서는 정해진 유효숫자로 지수를 이용해 유효숫자를 시프트해 크게 만들거나 작게 만든다!


###### 준정규값
- 0과 0이아닌 가장 작은 수사이에는 분명한 간격이 있다!
- `FLT_MIN` : 16진수로 0x00800000 (2진수 아님!)
```
 0x00800000
= 0000 0000 1000 0000 0000 0000 0000 0000
```

`std::numeric_limits<float>::min()` ==  `FLT_MIN`

**준정규값(denormalize Value)** : -`FLT_MIN` ~ +`FLT_MIN`까지를 꽉 채워 넣는다

> **정규수** : (e=1~254)
> 1.m × 2<sup>(e - 127)</sup>
> 
> **준 정규수** : (e=0)
> 0.m × 2<sup>(1 - 127)</sup>= 0.m × 2<sup>(e - 126)</sup>

0에 가까운 float 준 정규값 : `FLT_TRUE_MIN`이라는 상수로 표현된다.

float을 `==`으로 비교하는 경우는 많지 않지만,
``` cpp
if(a==b){ .. }
if(a-b == 0.f){ .. }
```
이 구문을 동일히 처리할 수있다.

- **머신 앱실론**(ε_m) 1 ≠1+ ε 를 충족하는 가장 작은 수
  : ε = 2⁻²³ ≈ 1.192 × 10⁻⁷ (IEE-754)
  - 가수가 23비트밖에 되지 않기 때문에
  - 더 작은수는 더해도 잘려나가겠다

###### **ULP** : Units in the Last Place
- 가장 낮은 유효숫자 값 제외하고 모두 같으면 : `1ULP`의 차이가 있다고 한다
- 1 ULP = 2<sup>x</sup> · ε
  `a≥b` == `a+1ULP > b`
- 너티독에서는 이를 활용해서 비교연산자를 쓰지않고,  `1ULP`을 더하거나 빼서 처리함!
- ULP(x) 그 숫자 x에서 float이 구분 가능한 최소 간격
  → 숫자 클수록 ULP 커져서 정밀도 떨어짐

- 절대 시간을 초, 부동소수로 담고있을때, 1/30(0.033)초를 더해도 아무 효과 없을정도는?
  지수의 한칸 간격이 23칸으로 정해져있기 떄문에
  반올림 기준이  지수가 19인 2<sup>-4</sup>(0.0625초)가 되기떄문에 0.033초는 작아서 무시된다

| 시간 값              | 지수     | 한 칸 간격           |
| ----------------- | ------ | ---------------- |
| 2¹⁹ 초 (약 6일)      | 19     | 2⁻⁴ = 0.0625초    |
| **2²⁰ 초 (약 12일)** | **20** | **2⁻³ = 0.125초** |

#### 3.3.2 기본적인 데이터 타입

- bool이라 하더라도 1bit로 구현하지는 않는다
- SIMD 연산자는 32비트 floatdmf 4개 합친  128bit register사용
- 1byte를 여러개 붙혀서 Multibyte사용 함
- `MSB(Most Significant Byte)`: 최상위 바이트,  `LSB(Least Significant Byte)` : 최하위 바이트
  `0xABCD1234` `MSB` : AB, `LSB`:34

|               | 메모리 크기    | 저장되는 바이트 순서            |
| ------------- | --------- | ---------------------- |
| Little-Endian | LSB < MSB | 0x34, 0x12, 0xCD, 0xAB |
| Big - Endian  | MSB < LSB | 0xAB, 0xCD, 0x12, 0x34 |

##### Endian 바꾸기
1. 각 Struct내의 데이터 멤버의 위치, 크기를 정확히 알고있어야함
2. 크기에 따라 멤버를 바꿔야함
-> struct 전체를 byte 배열로 두고 무작정 수정하면 안됨, 어떤 멤버를 수정하는지, 그 멤버가 몇 바이트인지 정확히 알고 멤버를 변환!

- 정수 바꾸기 : 
```cpp
struct Example
{
	U32 m_a;
	U16 m_b;
	U32 m_c;
}
void writeExampleStruct(Example& ex, Stream& stream)
{
	stream.writeU32(swapU32(ex.m_a));
	stream.writeU16(swapU16(ex.m_b));
	stream.writeU32(swapU32(ex.m_c));
}

inline U16 swapU16(U16 value){}
return ((value& 0x00FF)<<8) | ((value & 0xFF00) >> 8);
}

inline U32 swapU32(U32 value){
	return ( (value & 0x000000FF) << 24) | ( (value& 0x0000FF00)<<8) |
	( (value & 0x00FF0000) >>8) | ( (value & 0xFF000000)>>24 );
}

```
- 비트 시프트
	- 24 : 2진수 24칸(16진수 6칸) 왼쪽으로 이동,
	- 8 : 2진수 8칸(16진수 2칸) 이동
각각 16비트, 32비트에서 Endian을 정수로 바꿀 수있다.

- float 바꾸기 1 - 정수 타입의 포인터로 해석해버리기(**Type punning**)
  1. `reinterpret_cast<std::int32_t>`로 변환
  2. Endian바꾸는 연산
  3. 다시 `reinterpret_cast<std::float>`으로 cast 

- float 바꾸기 2 - Union을 쓰는 방법
``` cpp
union U32F32
    {
        U32 m_asU32;
        F32 m_asF32;
    };

inline F32 swapF32(F32 value)
    {
        U32F32 u;
        u.m_asF32 = value;
        u.m_asU32 = swapU32(u.m_asU32); //메모리 비트 뒤집음
        return u.M_asF32; //뒤집어 놓고 float 다시 return
    }
```

1. uion으로 U32 F32를 같은 메모리에 겹쳐놓고  
2. float 값을 메모리에 그대로 넣어놓고  
3. 같은 메모리를 uint32로 해석해서 바이트 스왑  
4. 그 뒤집은 비트 덩어리를 다시 float으로 해석

=> float 은 32비트의 데이터다!



#### 3.3.4 선언, 정의, 연결성

> 개별적인 번역단위(TU)에 있는 목적파일을 링커가 외부 참조로 해결한다.

- C/C++은 여러 TU로 이루어짐
- Compiler cpp 파일 1개 번역 -> 목적파일 1개
- 목적 파일 : 기계어 + 모든 전역 변수 / 정적 변수 + 미확정 참조
1. Compiler - 한번에 1개의 TU만을 처리 : 외부 전역변수/함수 처리시 외부 참조 있을꺼라고 가정
2. object 파일들을 모두 모아 완성된 exe로 만드는것이 링커의 몫.
3. 링커는 미확정상태의 외부참조 어떤건지 알아내려고 시도
4. 이 과정이 모두 성공하면 모든 함수, 전역/정적변수, TU간의 참조가 전부 포함된 실행파일이 만들어진다.
- 링커의 주된 역할 : 외부 참조 해결
  에러 01. **미확정 심볼(unresolved Symbol)** : 선언된 외부참조 못찾은 것.
  에러 02. **중복된 정의 심볼(multiply defined Symbol)** : 이름 같은 변수/함수를 2개 이상 발견.

##### 선언과 정의:
선언(declaration) : 데이터 객체, 함수 형태를 나타낸다  
정의(definition) : 프로그램 안에 고유한 저장공간을 나타낸다

선언과 동시에 정의를 하는 경우가 아닌, 헤더와 cpp파일에 떨어뜨려놓은 구현은
``` cpp
//A.h
void foo();
extern void foo();

//A.cpp
void A::foo()
{
cout<<"You Foo!"<<endl;
}
```
- 다른 TU에서 정의를 하는것이기에 사실 암묵적으로 `extern`이 붙는다
- 이것도 사실은 Linker가 연결 하고 있었음!

```cpp
//01 흔한 객체 접근 방식
```

- 정의를  헤더파일에 두는것은 좋지 못한 생각이다.

  아래 Inline에서는 예외이다.
###### Inline에서의 중복 정의?
`inline` : 함수의 코드가 호출된 곳에 직접 복사되기 때문

``` cpp
// speed.h
inline int GetSpeed() { return 100; }

// A.Cpp
#include "Speed.h"

// B.Cpp
#include "Speed.h"

// C.Cpp
#include "Speed.h"
```

컴파일러 입장에서는
- A.cpp ->GetSpeed 정의생성
- B.cpp ->GetSpeed 정의생성
- C.cpp ->GetSpeed 정의생성
=> 이를 Inline은 링커가 하나로 병합또는 무시함!
- 두군데 이상의 TU에서 같은 inline 함수 사용하기 위해서는 정의는 반드시 header 파일에 있어야함!


``` cpp
// inline 여러 TU에서 활용 못하는 예시
//foo.h

//foo.cpp
inlint int foo::max(int a, int b) { return (a>b) ? a : b ;}
```
- 위와 같이 header파일에 정의를, cpp에 구현을 하면 안됨!!
  -> Compiler가 인러인 함수 처리하려면, **컴파일러가 함수 구현을 볼 수있도**록 해야함
  -> 위 예제는 컴파일러가 함수 구현을 볼 수없다.(inline은 헤더에 선언/정의를 몰아줘야함)

| 가상 함수     | 인터페이스  | 구현 숨김 | 추상  |
| 템플릿       | 정의     | 없음    | 노출  |

#### 3.3.4.3 연결성
##### 1. 연결성(Linkage)
- 같은 이름이 **서로 다른 번역단위(TU)에서 같은 개체를 가리키는지**를 결정하는 속성
- 링커가 어떤 정의를 서로 다른 번역단위 간에 연결해 사용할지를 지시(?)
- 종류 : 외부 연결성 / 내부 연결성 / 무연결 (지역변수 등)
- 번역단위 (TU) : `#include`가 전부 펼쳐진 .cpp 하나
	- 헤더는 독립된 TU가 아닌, inluce한 각 .cpp 안으로 텍스트로 복사되어 들어감!

- 정의를 연결해 사용할지 지시라는 느낌보다, 이름이 가진 속성으로부터 Linker가 연결할지 안할지를 결정한다.(?)

##### 2. 외부연결성(`extern`)
- 다른 TU에서도 같은 이름이 같은 개체를 가리킨다
- `extern`은 정의 없이 선언만 만드는 키워드!
	- 다른 T에 있는 정의를 참조할때 사용
```cpp
extern int g_count; // 선언만!(정의없이)
int g_count =0; // 정의 (한 cpp에만)
```
##### 3. 내부연결성(`static`)
- 01) 전역/namespace 범위의 `static`은 이름을 **내부 연결성**으로 바꾼다 ( =숨기는 키워드)
- 02) 여러 cpp마다 같은 이름으로 정의하더라도, 서로 별개의 개체라서 **'중복 정의된 심볼'** 에러를 내지 않음
- 03) Linker에게 심볼이 export 되지 않으므로 다른 TU에서는 그 이름으로 접근 불가!

- 04) **주의!!!** :  아래와 완전히 다름
  1. 함수 안의 `static`(정적 지역변수)
     - 프로그램 종료까지 수명이 유지됨 - *정적 저장 기간*
  2. 클래스안의 `static`멤버
     - 클래스와 종속적이지 않음

###### 3-03) 다른 TU에서는 그 이름으로 접근 불가
```cpp

//Utils.h
static int Counter = 0;

void Foo();
int getCounter();

//Utils.cpp
#include "Utils.h"
void Foo(){	++Counter; }
int getCounter() {	return Counter; }

//main.cpp
#include <iostream>
#include "Utils.h"
int main()
{
    Foo();
    std::cout << "Main의 counter : " << Counter<< std::endl;
    std::cout << "Utils.cpp의 Counter : " << getCounter() << std::endl;
}
```
- `static`은 TU마다 개별적으로 **내부 연결성**이므로  복사본을 만들어준다.

-  `Counter` 는 `Utils.h`를 include한 .cpp마다 하나씩 생김 (헤더는 TU 아님!)
	- Utils.cpp : `Static Counter`하나
	-  main.cpp : `Static Counter`하나
	- 총 2개의 별개 변수임!! 
- 그래서 main이 직접 읽는 `Counter`는 0, Getter가 읽는 `Counter`는 1이 나온다.

##### 4.기본 연결성

| 대상                      | 기본 연결성                             |
| ----------------------- | ---------------------------------- |
| 비-const 전역 변수           | 외부 연결성                             |
| 함수                      | 외부 연결성                             |
| **`const` 전역 변수**       | **내부 연결성** (C++의 중요한 예외)           |
| `constexpr` 전역 변수       | 내부 연결성 (const 포함)                  |
| 익명(unnamed) 네임스페이스 안의 것 | 내부 연결성                             |
| 지역 변수                   | 연결성 없음                             |
| `inline` 함수/변수          | 외부 연결성이지만 ODR상 여러 번역 단위에서 중복 정의 허용 |
- non-const 전역변수/함수는 외부 연결성이 기본
- `const` / `constexpr`전역변수는 내부 연결성이 기본

- 파일 내부 전역 `static`보다 익명 네임 스페이스 `namespace {...}`를 권장!
- 헤더에 공유 전역 변수를 둘때는 `inline`변수가 정석!


##### 5.`static` 변수를 올바르게 쓰는 패턴! - 캡슐화
- `static`변수는 헤더가 아닌, .cpp에 둔다 → 복사본이 하나뿐!
- 밖에서는 이름이 보이지 않으므로, **외부 연결성 함수(getter)** 로 접근하기!

``` cpp
//Utils.h
void Foo();
int GetCounter();

//Utils.cpp
#include "Utils.h"
static int Counter =0 ; //Utils.cpp 전용
void Foo(){ Counter++; }
int GetCounter (){ return Counter; }

//main.cpp
Foo();
cout<< GetCounter(); //1
```
- main.cpp은 Counter 이름 모르고, `GetCounter()`를 호출하면 링커가 Utils.cpp의 `GetCounter`로 연결
- 연결성은 "이름이 보이냐"문제임. 참조/포인터 반환하면 이름이 숨겨진 변수도 외부에서 다를 수 있다!


##### 6. `static` vs `inline` - 헤더정의 둘때

| |`static` 함수|`inline` 함수|
|---|---|---|
|연결성|내부|**외부**|
|TU마다 정의가 있으면|**별개의** 함수가 TU마다 생김|링커가 **같은 하나의 함수**로 합침|
|헤더에 정의|가능하지만 중복/공유 문제|**정석** (ODR이 동일한 정의의 중복을 허용)|

- 단, inline 함수는 헤더파일에서 선언 및 정의를 해도 된다. **외부 연결성**이기 때문  
	ODR이 `inline`에 한해, 여러 TU에 동일한 정의 있는것 허용(3.3.4절)하기 때문
	- `Static`함수 : TU마다 별개의 함수 - 내부 연결성
	- `inline`함수 : TU마다 정의 있더라도 같은 하나의 함수 - 외부 연겨럿ㅇ

``` cpp
// Mysogi.h
inline int add(int a, int b)
{
	return a+b;
}

// Asogi.cpp
#include "Mysogi.h" // add inline 함수 정의가 A.cpp에 물리적 복사
// 전처리후
inline int add(int a, int b)
{
	return a+b;
}

// Bsogi.cpp
#include "Mysogi.h" // add inline 함수 정의가 B.cpp에도 물리적 복사

//전처리 이후 (include 부분이 인라인 함수의 파일내용 대체)
inline int add(int a, int b)
{
	return a+b;
}
```

| 목적                  | 방법                                       |
| ------------------- | ---------------------------------------- |
| 함수를 여러 cpp에서 사용     | 헤더에 선언, 한 cpp에 정의 (`static` 없이)          |
| 전역 변수를 공유           | 헤더에 `extern int g;`, 한 cpp에 `int g = 0;` |
| 헤더에 구현까지            | 함수는 `inline`, 변수는 `inline` 변수 (C++17)    |
| 한 cpp 안에서만 쓰는 헬퍼/상태 | 익명 네임스페이스 (또는 `static`)                  |

- 선언은 이름과 타입을 컴파일러에 알리기만 한다. 메모리에 저장 공간을 실제 할당하는것이 아님!
  - 서로 다른 T의 선언들이 같은 개체를 가리키면 외부연결성, 각자 별개의 개체면 내부연결성.
  - 함수 코드는 Text영역, 전역/정적 변수는 data/bss 영역에 프로그램 시작부터 존재하고, stack에는 함수 호출시 지역변수와 매개변수만 생긴다.

## 메모리 레이아웃 비교
```
디스크 파일              메모리
┌─────────────┐         ┌─────────────┐
│ .text       │  →      │ .text       │ (R+X)
│ .rdata      │  →      │ .rdata      │ (R)
│ .data       │  →      │ .data       │ (R+W)
│ .bss (0byte)│  →      │ .bss (큼)    │ (R+W, 0으로 채움)
│ .rsrc       │  →      │ .rsrc       │ (R)
└─────────────┘         └─────────────┘

// 왜 BSS는 0바이트인가? 
// -> 파일 크기 절약!
```
  
**1. text code**
- 실행 코드   
- 읽기 실행 권한(Read + Execute)  
- 코드 변조 방지를 위한 쓰기불가

**2. data(Initialize Data)**
- 초기화된 전역 / 정적 변수
- 읽기 + 쓰기 권한

```
// .data에 저장
int globalCounter = 100;
static float gravity = 9.8f;
```


**3. bss(Unitialized Data)**
- Block Started by symbol
- 초기화 되지 않은 전역 / 정적 변수
``` cpp
// .bss에 저장
int sogiArray[10000];
static char buffer[4096];
```

- 디스크 파일에는 실제 데이터 차지 않음!
- 메모리 로드시 0으로 초기화!


 **4. rdata / .rodata(Read - Only Data)**
``` cpp
.rdata
const char* message = "Hello";
const int MAX_PLAYERS = 64;
```
- 읽기 전용 데이터
- 상수, 문자열 리터럴 등  
  
**5. .rsrc (Resources) - Windows 특화**  
- 아이콘, 비트맵, 다이얼로그 등
``` cpp
// 게임 엔진활용 예시

// .text
void Update(float deltaTime) { /* 게임 로직 */ }

//.rdata
const char* LEVEL_NAMES[] = {"Tutorial", "Level1", "Boss"};
const float PI = 3.14159f;

//.data
int currentScore = 0;
GameState g_gameState = MENU;

//.bss
Entity entities[10000];
char textureCache[1024*1024];
// 큰 배열이지만 파일엔 0바이트!
```
  

> Q) void는 실행 코드니 .text로 들어가겠지만,  virtual로 선정된다면 .text로 들어가면 안될텐데?  
>   
> **A)**  .text에 들어가지만 추가 요소가 생긴다
> .text에 실제 코드가 들어가고, .rdata에 vtable이 들어간다!

  

**virtual 함수의 차이**

```cpp
class Enemy{
public :
	virtual void Attack(){}
    void move(){}
};

// vtable (가상 함수 테이블)
```

```
Enemy 클래스
├─ vtable → .rdata 섹션 (읽기전용 함수 포인터 배열)
│   ├─ Attack 함수 주소
│   ├─ 소멸자 주소
│   └─ ...
└─ 실제 함수들 → .text 섹션
```

``` cpp
Enemy enemy;  // 객체는 .data 또는 스택/힙

// 객체 내부 구조:
┌─────────────┐
│ vptr ───────┼─→ vtable (.rdata)
│             │     ├─ Attack 주소 → .text
│ member vars │     └─ ~Enemy 주소 → .text
└─────────────┘


// 섹션 배치

.text    : Attack(), Move() 실제 코드
.rdata   : vtable (함수 포인터 배열)
.data    : enemy 객체 (vptr 포함)
```

  

정리
- 함수 코드 자체 : 항상 .text
- virtual 차이 : vtable이라는 함수 포인터 배열이 .rdata에 추가!

#### 함수 내부 static vs 전역 static

static의 오해(나만의 오해일지도..?)

1. 전역 static(내부 연결성)
`static int sogi = 0;`

2. 함수 내부 static(지역 변수만이 아님!)

```cpp
void GetCallThis(){

	static int counter = 0; //딱 한번만 초기화
    return counter ++; // 함수 끝나도 값 유지!
}

GetCallThis(); // 0 return, counter == 1
GetCallThis(); // 1 return, counter == 2
GetCallThis(); // 1 return, counter == 3
```

- **싱글 톤 패턴**으로도 사용할 수 있음.

#### 이중 포인터의 메모리 확인

``` cpp
void someFunction() //스택영역
{
    Foo* pAnotherFoo = new Foo;

    Foo** ppFoo = new Foo*;
    (*ppFoo) = pAnotherFoo;
}
```

**포인터를 품은 포인터**:
```
[스택]                    [힙]
pAnotherFoo ──────────→ Foo 객체
                          ↑
ppFoo ──────→ Foo* 공간 ──┘
```

**전체 그림**:
```
[스택 영역 - someFunction 프레임]
┌─────────────────────────┐
│ pAnotherFoo: 0x1234     │──┐
│ ppFoo: 0x5678           │─┐│
└─────────────────────────┘ ││
                            ││
[힙 영역]                   ││
┌─────────────────────────┐ ││
│ 0x5678: 0x1234          │←┘│ (Foo* 저장 공간)
│ 0x1234: Foo 객체        │←─┘
└─────────────────────────┘
```

  

→ 포인터를 쓰면 힙만을 쓰는것이 아닌, 
Hip 영역 : 주소를 동적으로 갖는다
Stack 영역 : 주소를 담고있는 변수

#### 3.3.6.1 클래스 정적 멤버

**static**의 세가지 활용법
01 **파일 범위**에서의 선언, 구현 : 내부연결성 || UE에서 .cpp에서  
02 **함수 내부**에서의 선언, 구현 : 전역 변수  
03 **구조체, 클래스**에서의 선언

``` cpp
class Player {
public:
    string name;           // 각 플레이어마다 다른 이름
    static int totalCount; // 전체 플레이어 수 (공유!)
    
    Player(string n) : name(n) {
        totalCount++;  // 객체 생성될 때마다 카운트
    }
};

// 클래스 외부에서 반드시 정의 (메모리 할당)
int Player::totalCount = 0;

// 사용
Player p1("철수");  // totalCount = 1
Player p2("영희");  // totalCount = 2
Player p3("민수");  // totalCount = 3

cout << Player::totalCount;  // 3 (클래스 이름으로 접근)
cout << p1.totalCount;       // 3 (객체로도 접근 가능, 하지만 같은 변수)
cout << p2.totalCount;       // 3 (모두 같은 값
```

#### 3.3.7.1 메모리 정렬과 패킹

- 작은 데이터 멤버가 큰 멤버 사이에 들어가면 비효율 적으로 패킹되게 저장함.

CPU는 메모리에서 데이터를 읽을 때 워드단위(4바이트 / 8바이트)씩 읽는다.  
데이터가 정리 되어있어야지 한번의 메모리 접근을 할 수있겠다

``` cpp
struct sogi{
	char s;		// 1 byte
    int g;		// 4 byte
    char i; 		// 1 byte
};

주소  0,  1byte : s 주소
주소 1~3, 3yte : padding
주소 4~7, 4byte : g 주소
주소  8,  1byte : i 주소
주소 9~11, 3byte : padding
```

  

주요 규칙
- 1 byte (char) : 어떤 주소 상관 없음
- 2 byte (short, bool) : 2의 배수 주소( 0, 2, 4, 6 ...)
- 4 byte(int, float) : 4의 배수 주소(0, 4, 8, 12) : 32bit 프로그램의 배수주소
- 8 byte(double, longlong) : 8의 배수 주소(0, 8 , 16, 24) :64 bit 프로그램의 배수 주소

``` cpp
struct Data{
	char a; 	//1 byte
    char* ptr;	//32bit : 4byte, 64bit: 8byte
    int b;		//4 byte
};
```
