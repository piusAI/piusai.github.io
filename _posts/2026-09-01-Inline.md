여러 다른 CPP 파일에 복사해서 들어가면 안될때 활용하는 Inline!

ODR 규칙, 단일 정의 규칙은 **Compile 과정**중
1. 각 `.cpp`파일이 독립적으로 컴파일 되어서 .obj가 되도록
2. 링커가 이 `.obj`파일을 모아서 하나의 실행파일로 합친다

라는 과정을 거칠때, 단 하나만 읽도록 해야한다.

ODR : One Definition Rule  
> 하나의 개체(변수, 함수, 클래스 등)는 전체 프로그램을 통틀어 정의(Defiintion)이 딱 하나만 있어야한다 

근데 여러 파일에 정의하는 경우도 있을 수 있겠는데  그때 `inline`을 활용한다

## inline
여러 .cpp 파일에 각각 정의되더라도 링커 에러가 나지않도록!
 
### Code 예시
``` cpp
// Utils.h
#pragma once

int Add(int a, int b) {return a+ b;} //함수 정의가 헤더자체에 있다
```

```cpp
// A.cpp
#include "Utils.h"
```

```cpp
// B.cpp
#include "Utils.h"
```
이렇게 Translation Unit이 다르다면, `#pragma once`로써만 관여할 수없다.

```
inline int Add(int a, int b){return a+b;}
```

이렇게 된다면, 여러 Obj파일에 **중복**으로 나타나도 괜찮다


### UE의 FORCEINLINE?

```
#define FORCELINE inline
```
UE의 `FORCELINE`은 inline의 의미 에다가
compiler에게 진짜 inline해라!
"함수 호출 자체를 없애고 그자리에 박아넣어라"는 강제 힌트를 넣은 것

1. **ODR(One Definition Rule)** 관점 : Header에 정의를 두더라도 링커 에러 나지 않도록!
2. 성능 관점 : 함수 호출 Overhead 없애도록 강하게 요청(`inline`이상의 강제성)
