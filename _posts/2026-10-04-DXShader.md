PS, VS를 읽어들이기 위한 Semantic, HLSL을 compile해서 변수를 불러 들이는 것까지 정확하게 DirectX11에서 이해하고 활용하고 싶다.

DirectX에서 하던 Shader를 Compile부터 연동의 흐름을 한번 정리하고 싶었다.  
DX의 구조체는 백지에서 모두 쓰지 못하더라도 HLSL에서의 세부적인 조정과 Shader를 다루기위한 기초 초석은 내가 잡아야한다 생각했다.

Tree의 전반적인 형태를 이해한 다음 subgraph처럼 이해할 수있었던 `priority_queue`의 자료구조 이해처럼, [Graphics RenderPipeline](https://piusai.github.io/graphics/2026/05/29/RenderPipeline.html)을 전반적으로 이해한 후에야 Shader의 형태가 눈에 살짝씩 잡히기 보이기 시작했다.  


이번 글에서는 `ColorShaderClass.cpp`에서 `.hlsl`로 Shader가 흘러들어오는쪽에 집중하였고, Object단일 Mesh를 Shader Compile하는데에 집중했다.

### 1. Shader Initialize | 초기화 (1회) 

**Class Member Variable** / **Local Variable**:  

```cpp
// colorshaderclass.h
ID3D11VertexShader* m_vertexShader;
ID3D11PixelShader* m_pixelShader;
ID3D11InputLayout* m_layout;
ID3D11Buffer* m_matrixBuffer; // VS 상수버퍼 (world/view/projection) - 이걸 matrix buffer에 다 채울것

// ColorShaderclass.cpp
bool InitializeShader(ID3D11Device* device, HWND hwnd, const WCHAR *fileName )
{
	HRESULT result; //함수 호출 결과 받을 객체
	ID3D10Blob* vertexShaderBuffer; // VS compile결과 (바이트 코드)
	ID3D10Blob* pixelShaderBuffer; //PS compile결과 (바이트 코드)
	D3D11_INPUT_ELEMENT_DESC polygonLayout[2]; //Input Layout 요소 2개 (POSITION,  COLOR)
	D3D11_BUFFER_DESC matrixBufferDesc; // Constant buffer 생성 Desc(World/view/projection)
	ID3D10Blob* errorMessage; // Compile 에러 받을라고
...
}
```

#### 1.0 Keyword : Blob / ByteCode
- **Blob**(`ID3DBlob`, `ID3D10Blob`): 크기가 있는 범용 메모리 덩어리
  - `GetBufferPointer()`로 시작주소, `GetBufferSize()`로 크기를 얻는다.
  -  컴파일 결과물도 담고, 에러 메세지 텍스트(`errorMessage`)도 담는다.
- **ByteCode(DXBC)**: HLSL을 `D3DCompile`로 컴파일한 중간 결과
  - GPU가 바로 실행하는 기계어가 아니다.
  - `CreateVertexShader`를 호출할때 driver가 GPU전용 명령어로 다시 변환한다.
- `CreateInputLayout`에 vs바이트 코드를 넘기는 이유 : **검증용**
  - Layout이 VS의 입력 시그니쳐 (`POSITION`, `COLOR`)와 맞는지 확인

#### 1.1 D3DCompileFromeFile

``` cpp
...
// 01 Compile ( HLSL -> 바이트 코드 Blob) : PS,VS
result = D3DCompileFromFile(fileName, NULL, NULL, "ColorVertexShader", "vs_5_0", 
	D3D10_SHADER_ENABLE_STRICTNESS, 0, &vertexShaderBuffer, &errorMessage);
	//실패시 errorMessage Blob출력 - Shader 디버깅 핵심

result = D3DCompileFromFile(fileName, NULL, NULL, "ColorPixelShader", "ps_5_0",
		D3D10_SHADER_ENABLE_STRICTNESS, 0, &pixelShaderBuffer, &errorMessage);
```

- Entry Point 이름(`ColorVertexShader`, `ColorPixelShader`)과 Target(`vs_5_0`, `ps_5_0`)을 넘김
- `D3DCompileFromFile`의 결과물은 `ID3D10Blob`에 담긴 Compiled ByteCode(DXBC)

#### 1.2 CreateVS/PS

``` cpp
// 02 바이트 코드 -> shader 객체 생성
...
result = device->CreateVertexShader(vertexShaderBuffer->GetBufferPointer(), vertexShaderBuffer->GetBufferSize(), NULL, &m_vertexShader);

result = device->CreatePixelShader(pixelShaderBuffer->GetBufferPointer(), pixelShaderBuffer->GetBufferSize(), NULL, &m_pixelShader);

```
  
- ByteCode를 `CreateVS/PS`이 받아 GPU용 Shader 객체(`ID3D11VertexShader`, `ID3D11PixelShader`)로 만든다.


#### 1.3 CreateInputLayout

```cpp
// 03. Vertex Input Layout 생성 (C++ 정점 구조체 ↔ HLSL VertexInputType)
polygonLayout[0].SemanticName         = "POSITION";                   // HLSL의 POSITION과 매칭
polygonLayout[0].SemanticIndex        = 0;
polygonLayout[0].Format               = DXGI_FORMAT_R32G32B32_FLOAT;  // XMFLOAT3
polygonLayout[0].InputSlot            = 0;
polygonLayout[0].AlignedByteOffset    = 0;
polygonLayout[0].InputSlotClass       = D3D11_INPUT_PER_VERTEX_DATA;
polygonLayout[0].InstanceDataStepRate = 0;

polygonLayout[1].SemanticName         = "COLOR";                      // HLSL의 COLOR와 매칭
polygonLayout[1].SemanticIndex        = 0;
polygonLayout[1].Format               = DXGI_FORMAT_R32G32B32A32_FLOAT; // XMFLOAT4
polygonLayout[1].InputSlot            = 0;
polygonLayout[1].AlignedByteOffset    = D3D11_APPEND_ALIGNED_ELEMENT; // = 12
polygonLayout[1].InputSlotClass       = D3D11_INPUT_PER_VERTEX_DATA;
polygonLayout[1].InstanceDataStepRate = 0;

unsigned int numElements = sizeof(polygonLayout) / sizeof(polygonLayout[0]);

result = device->CreateInputLayout(polygonLayout, numElements,
	vertexShaderBuffer->GetBufferPointer(),   // VS 입력 시그니처 검증용
	vertexShaderBuffer->GetBufferSize(), &m_layout);

```

- **Semantic이름 + Index**로 HLSL의 `VertexInputType`과 연결. 이름이 안맞으면 `CreateInputLayout` 실패
- 생성 끝나면 `vertexShaderBuffer`, `pixelShaderBuffer`는 Release.


#### 1.4 CreateBuffer
- Constant buffer를 만들고, 그 buffer를 가리키는 핸들을 `m_matrixBuffer`에 저장
- HLSL의 `cbuffer`는 `m_matrixBuffer`라는 이름은 모르고, 슬롯번호(`b#`)로만 연결됨

``` cpp

...
// 04. Constant Buffer생성 (매프레임 CPU가 갱신 -> Dynamic)
matrixBufferDesc.Usage = D3D11_USAGE_DYNAMIC;	// The buffer is updated each frame.
matrixBufferDesc.ByteWidth = sizeof(MatrixBufferType); //16바이트 배수
matrixBufferDesc.CPUAccessFlags = D3D11_CPU_ACCESS_WRITE;	// Writing data by CPU

...

result = device->CreateBuffer(&matrixBufferDesc, NULL, &m_matrixBuffer);
return true;
}
```
- `D3D11_USAGE_DYNAMIC`, `CPU_ACCESS_WRITE`로 생성 되어있어야 **(2.1)단계의 Map-Unmap**이 가능하다
- 초기화 단계에서 `MatrixBufferType`은 크기 계산용으로만 쓰임
- 슬롯(`register(b#)`)과의 연결은 여기가 아닌, Update단계의의 `VSSetConstantBuffers`에서 일어난다

#### 1.5 주의! 반드시 매칭하소!

| C++ 정점 구조체          | InputElementDesc                         | HLSL 입력 구조체                  |
| ------------------- | ---------------------------------------- | ---------------------------- |
| `XMFLOAT3 position` | `POSITION`, `R32G32B32_FLOAT`, offset 0  | `float4 position : POSITION` |
| `XMFLOAT4 color`    | `COLOR`, `R32G32B32A32_FLOAT`, offset 12 | `float4 color : COLOR`       |

> C++는 `XMFLOAT3`, HLSL은 `float4`인 이유 : IA가 빠진 w성분(동차좌표) 을 자동으로 1로 채워준다. 그럼에도 hlsl에서 `input.position.w = 1.0f`로 명시!

### 2. Shader Update Frame | 업데이트 (매 frame/Draw마다)
- `ColorShaderClass::Render`가 wrapper로써 `SetShaderParameters`→`RenderShader`를 순서대로 호출

#### 2.1.0 `::SetShaderParameters`
**Class Member Variable** / **Local Variable**:  

``` cpp
bool ColorShaderClass::SetShaderParameters(ID3D11DeviceContext* deviceContext, XMMATRIX worldMatrix, XMMATRIX viewMatrix, XMMATRIX projectionMatrix)
{
HRESULT result;
D3D11_MAPPED_SUBRESOURCE mappedResource; //GPU 버퍼에 쓸수있는 주소를 담은 struct
MatrixBufferType* dataPtr;
unsigned int bufferNumber;


//전치 : Shader를 위한 전치 행렬준비 - vs돌리기위한 matrix
worldMatrix = XMMatrixTranspose(worldMatrix);
viewMatrix = XMMatrixTranspose(viewMatrix);
projectionMatrix = XMMatrixTranspose(projectionMatrix);


```
- `D3D11_MAPPED_SUBRESOURCE` 구조체는 GPU buffer에 쓸 수있는 주소를 담은 구조체
- **Transpose(전치)**의 이유
  1. DirectXMath는 row-major저장, hlsl 기본은 column-major로 읽음
  2. HLSL에서 `#pragma pack_matrix(row_major)`또는 `row_major matrix`로 선언하면 전치 없이도 가능


#### 2-1. map/Unmap

```cpp
// CPU가 GPU 버퍼 메모리에 쓸 수 있도록 포인터 받음
result = deviceContext->Map(m_matrixBuffer, 0, D3D11_MAP_WRITE_DISCARD, 0, &mappedResource);
...


dataPtr = (MatrixBufferType*)mappedResource.pData; //pData : 쓸수있는 메모리 시작주소
dataPtr->world = worldMatrix;
dataPtr->view = viewMatrix;
dataPtr->projection = projectionMatrix;

//반드시 Unmap! GPU가 갱신된 버퍼를 사용할수있도록!
deviceContext->Unmap(m_matrixBuffer, 0);

```

- 순서 : `Map` → `행렬 복사` → `Unmap`
   - Unreal engine GT의 구조체를 람다 캡쳐 복사로 생성해서 RenderThread 보내는거와 비슷함

1. CPU쪽 작업이다 (vs가 lock하는게 아님).
2. `Map` : CPU가 GPU 리소스 메모리에 쓸 수있는 포인터를 받는다
3. `Unmap` : 다시 돌려준다  (이후 `pData`접근하면 포인터 유효하지 않음.)
4. D3D9에서는 `Lock/Unlock`이었고 D3D10이후 `Map/Unmap`으로 바뀌었다
5. `D3D11_MAP_WRITE_DISCARD` : 이전 내용은 버리고 새로 쓴다. 드라이버가 내부적으로 새 메모리를 renaming하기 때문에, GPU가 이전 프레임 데이터를 쓰는 중이라도 CPU가 기다리지 않는다.
6. 이 방식은 버퍼가 `USAGE_DYNAMIC` + `CPU_ACCESS_WRITE`로 생성 되어있어야 가능


#### 2-2 VSSetConstantBuffers

``` cpp
...
//VS에서 update된 상수 buffer를 최종 set
bufferNumber=2; //일부러 2로 설정 -> 이후 hlsl에서 register(b2)로 받음

// Constant buffer slot(b2)에 바인딩
deviceContext->VSSetConstantBuffers(bufferNumber, 1, &m_matrixBuffer);
return true;
}
```

- Slot번호가 `register(b#)`와 연결되는 **실제 지점**
- (실험) `bufferNumber=2`로 바꾸면 HLSL에서 `register(b2)`로 바꿔야 함!




#### 2.3.0 `::RenderShader`

**Class Member Variable** / **Local Variable**:  

```cpp
void ColorShaderClass::RenderShader(ID3D11DeviceContext* deviceContext, int indexCount)
{
	// 03. Vertex Input Layout Set!
	deviceContext->IASetInputLayout(m_layout);
	
	// 03. Triangle Render할때 쓸 VS, PS를 Set!
	deviceContext->VSSetShader(m_vertexShader, NULL, 0);
	deviceContext->PSSetShader(m_pixelShader, NULL, 0);
	
	// 04. 삼각형 그려라!
	deviceContext->DrawIndexed(indexCount, 0, 0);
}
```

- `DrawIndexed`: `index count`개의 index 분량을 그리라는 명령, 실제 처리는 GPU가 병렬로 수행

### 3. HLSL (colorShader.hlsl)

``` cpp
//colorShader.hlsl

// SetShaderParameter에서 올린 ConstantBuffer 변수들 받는다.
cbuffer MarixBuffer : register(b2)
{
	matrix worldMatrix;
	matrix viewMatrix;
	matrix projectionMatrix;
};


struct VertexInputType
{
	float4 position : POSITION;
	float4 color : COLOR;
};

struct PixelInputType
{
	float4 position : SV_POSITION;
	float4 color : COLOR;
	//float2 tex:TEXCOORD0; //이 쉐이더에서는 안씀!
};

PixelInputType ColorVertexShader(VertexInputType input)
{
	PixelInputType output;
	
	input.position.w = 1.0f;
	
	//vs 행렬 돌리기
	output.position = mul(input.position, worldMatrix);
	output.position = mul(output.position, viewMatrix);
	output.position = mul(output.position, projectionMatrix);
	
	output.color = input.color;
	
	return output;
}

//보간된 input color를 그대로 출력
float4 ColorPixelShader(PixelInputType input) : SV_TARGET
{
	return input.color;
}
```
- Semantic은 연결 이름표, 데이터 나르는(Convey)것은 Semantic아님! **Buffer**임!!
- 일반 Semantic : (`POSITION`, `COLOR`, `TEXCOORD0`등) : IA->VS->PS단계에서 같은 이름끼리 연결하는 **매칭 규약**
- `SV_`는 **System Value**로, pipeline이 특별한 의미를 아는 값 (`SV_POSITION`, `SV_TARGET` 등)  [System Value Semantic 참고](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-semantics)

#### 3.1 슬롯 연결 확인(C++ ↔ HLSL);

``` cpp
//colorshaderclass.cpp
unsigned int bufferNumber = 2;
VSSetConstantBuffers(bufferNumber, 1, &m_matrixBuffer);
//bufferNumber(StartSlot) = 2 → register(b2)와 매칭

//.hlsl
cbuffer MatrixBuffer : register (b2)
{
matrix worldMatrix;
matrix viewMatrix;
matrix projectionMatrix;
}
```

- **Cbuffer Matrix**의 이름은 그냥 이름표.
  - C++와는 `register(b#)`슬롯 번호와 메모리 레이아웃(멤버 순서/크기)으로 연결


#### 3.2 VertexInputType vs PixelInputType

|구조체|데이터 출처|시맨틱 연결 방법|
|---|---|---|
|`VertexInputType`|버텍스 버퍼 (C++)|`D3D11_INPUT_ELEMENT_DESC`의 `SemanticName`|
|`PixelInputType`|VS 출력|HLSL 시맨틱끼리 매칭 (C++ 설정 없음)|

- `PixelInputType`의 `SV_POSITION`은 VS가 낸 **ClipSpace** 좌표를 Rasterizer가 **화면(Viewport)** 좌표로 변환해서 PS에 넘겨 준 값이다.
- `COLOR` 등 나머지 값은 VS 출력이 삼각형 안에서 **보간**되어 전달된다.




#### 3.3 VS / PS Flow
**VS**:  
1. GPU에서 VS를 호출하고, vertex buffer에서 data processing한다.
2. vertex buffer의 개별 Vertex 마다 한번씩 실행된다
3. vs의 output은 Rasterizer를 거쳐 pixelshader로 전달된다.
	- `SV_POSITION`은 Clip 공간 좌표 → Rasterizer가 Viewport 변환
	-  나머지 출력(Color 등)은 보간(**interpolation**)된다.

→ **Rasterizer**의 NDC/Viewport변환은 고정 기능이라 자동으로 한다! 단, viewport크기는 `RSSetViewports`로 설정!
- Vertex Buffer 데이터 포맷과 VS의 input은 일치해야 한다


**PS**:  
1. 화면에 렌더링 된 Polygon 위의 매 pixel마다 실행된(그린)다
2. PS는 VS output 자체가 아니라 **Rasterizer**가 **보간한 값**을 받는다

### 4. Semantic vs register

|     | Semantic                                        | register                      |
| --- | ----------------------------------------------- | ----------------------------- |
| Ex  | `POSITION`, `COLOR`, `SV_POSITION`, `TEXCOORD0` | `b0`, `t0`, `s0`, `u0`        |
| 용도  | **스테이지 간 데이터 연결**  <br>(IA→VS→PS 입출력 매칭)        | **CPU가 바인딩한 리소스를 셰이더 변수에 연결** |
| 대상  | 정점/픽셀 입출력 변수                                    | 상수 버퍼, 텍스처, 샘플러, UAV          |

#### 4.1 register 접두사

| 접두사  | 의미          | C++ 바인딩 함수                        |
| ---- | ----------- | --------------------------------- |
| `b#` | 상수 버퍼       | `VSSetConstantBuffers(slot, ...)` |
| `t#` | 텍스처 / SRV   | `PSSetShaderResources(slot, ...)` |
| `s#` | 샘플러         | `PSSetSamplers(slot, ...)`        |
| `u#` | UAV (컴퓨트 등) | `CSSetUnorderedAccessViews`       |

 - texture를 가져오려면 `SetShaderParameter::SetShaderResource`에서 넣어주어야 hlsl코드내에서 `Texture2D`를 가져올 수있음

- SRV: ShaderResource View

| 스테이지 | 상수 버퍼                  | SRV                    | 샘플러             |
| ---- | ---------------------- | ---------------------- | --------------- |
| VS   | `VSSetConstantBuffers` | `VSSetShaderResources` | `VSSetSamplers` |
| PS   | `PSSetConstantBuffers` | `PSSetShaderResources` | `PSSetSamplers` |
| CS   | `CSSetConstantBuffers` | `CSSetShaderResources` | `CSSetSamplers` |

```cpp
cbuffer MatrixBuffer : register(b0) { ... }
Texture2D    shaderTexture : register(t0);
SamplerState sampleType    : register(s0);
```

- `VSSetConstantBuffers(bufferNumber, ...)`의 `bufferNumber`가 **b 슬롯 번호**다.
- register를 생략하면 컴파일러가 선언 순서대로 0번부터 자동 배정한다.  
  버퍼가 여러 개가 되면 명시하는 게 안전하다.
- 텍스처를 쓰게 되면 `TEXCOORD0`(semantic, 정점 입력)과 `t0`/`s0`(register, 리소스)을 같이 쓴다.

### 5. 파이프라인 단계와 코드 매핑

| 파이프라인 단계(프로그래밍 O/X ) | 관련 코드                                                        |
| -------------------- | ------------------------------------------------------------ |
| IA (X)               | `CreateInputLayout`, `IASetInputLayout`, vertex/index buffer |
| VS(O)                | `CreateVertexShader`, `VSSetShader`, `VSSetConstantBuffers`  |
| Rasterizer  (X)      | 보간, 뷰포트 변환                                                   |
| PS(O)                | `CreatePixelShader`, `PSSetShader`                           |
| OM(X)                | RT / DepthStencil (`SV_TARGET`으로 출력)                         |

- Rasterizer와 OM설정은 `D3DClass`초기화에서 이루어 짐.

### 6. 추가 메모

- **Constant Buffer 16바이트 정렬**: cbuffer 크기는 16바이트 배수여야 한다.  
  `float3` 뒤에 `float`가 안 오면 패딩이 필요하다 (라이트 방향 등을 넣을 때 바로 부딪힘).
- **해제(Shutdown)**: `m_matrixBuffer`, `m_layout`, `m_pixelShader`, `m_vertexShader` 순으로 Release. 컴파일 후 Blob Release도 잊지 말 것.
- **에러 처리**: `errorMessage` Blob을 `OutputShaderErrorMessage` 등으로 출력하는 부분이 셰이더 디버깅의 핵심.
- DX11은 Window/Device에 raw하게 붙어서 하기 때문에 구조체가 번거롭지만, 그만큼 메모리에 정확히 무엇을 꽂아 넣는지 이해하기 좋다.
