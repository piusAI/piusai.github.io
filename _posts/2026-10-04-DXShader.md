PS, VS를 읽어들이기 위한 Semantic, hlsl로 compile해서 변수를 불러 들이는 것까지 정확하게 DirectX11에서 이해하고 활용하고 싶다.

DirectX에서 하던 Shader를 Compile부터 연동의 흐름을 한번 정리하고 싶었다.
DX의 구조체는 백지에서 모두다 쓰지 못하더라도 hlsl에서의 세부적인 조정과 shader를 다루기위한 기초 초석은 내가 잡아야한다 생각했다.

Tree의 전반적인 형태를 이해한 다음 subgraph처럼 이해할 수있었던 `priority_queue`의 자료구조 이해처럼, [Graphics RenderPipeline](https://piusai.github.io/graphics/2026/05/29/RenderPipeline.html)을 전반적으로 이해한 후에야 Shader의 형태가 눈에 살짝씩 잡히기 보이기 시작했다.

### 1. 초기화 | Initialize (1회) 

##### 1-1. Memeber

```cpp
// colorshaderclass.h
ID3D11VertexShader* m_vertexShader;
ID3D11PixelShader* m_pixelShader;
ID3D11InputLayout* m_layout;
ID3D11Buffer* m_matrixBuffer; // VS 상수버퍼 (world/view/projection) -이 matrix buffer에 다 채울것
```

##### 1-2. InitializeShader
``` cpp
// ColorShaderclass
bool InitializeShader(ID3D11Device* device, HWND hwnd, const WCHAR *fileName )
{
	HRESULT result; //함수 호출 결과 받을 객체
	ID3D10Blob* vertexShaderBuffer; // VS compile결과 (바이트 코드)
	ID3D10Blob* pixelShaderBuffer; //PS compile결과 (바이트 코드)
	D3D11_INPUT_ELEMENT_DESC polygonLayout[2]; //Input Layout 요소 2개 (POSITION,  COLOR)
	D3D11_BUFFER_DESC matrixBufferDesc; // Constant buffer 생성 Desc(World/view/projection)
	ID3D10Blob* errorMessage; // Compile 에러 받을라고


...
// 01 Copmile ( HLSL -> 바이트 코드 Blob) : PS,VS
result = D3DCompileFromFile(fileName, NULL, NULL, "ColorVertexShader", "vs_5_0", 
	D3D10_SHADER_ENABLE_STRICTNESS, 0, &vertexShaderBuffer, &errorMessage);
	//실패시 errorMessage Blob출력 - Shader 디버깅 핵심

result = D3DCompileFromFile(fileName, NULL, NULL, "ColorPixelShader", "ps_5_0",
		D3D10_SHADER_ENABLE_STRICTNESS, 0, &pixelShaderBuffer, &errorMessage);
		
...


// 02 바이트 코드 -> shader 객체 생성 : Buffer로부터 VS, PS생성
result = device->CreateVertexShader(vertexShaderBuffer->GetBufferPointer(), vertexShaderBuffer->GetBufferSize(), NULL, &m_vertexShader);

result = device->CreatePixelShader(pixelShaderBuffer->GetBufferPointer(), pixelShaderBuffer->GetBufferSize(), NULL, &m_pixelShader);



// 03 Input Layout (IA 단계) - Semantic으로 vtx data, VS 입력 연결
polygonLayout[0].SemanticName = "POSITION";
polygonLayout[0].Format = DXGI_FORMAT_R32G32B32_FLOAT;
..
polygonLayout[1].SemanticName = "COLOR";
polygonLayout[1].Format = DXGI_FORMAT_R32G32B32A32_FLOAT;

// VS byte 코드 넘기는 이유 : VS의 입력 시그니처와 layout이 맞는지 검증
result = device->CreateInputLayout(polygonLayout, numElements, vertexShaderBuffer->GetBufferPointer(), vertexShaderBuffer->GetBufferSize(), &m_layout);

// Blob 필요없으니 해제
vertexShaderBuffer->Release();
pixelShaderBuffer->Release();

// 04. Constant Buffer생성 (매프레임 CPU가 갱싱 -> Dynamic)
...
matrixBufferDesc.ByteWidth = sizeof(MatrixBufferType); //16바이트 배수
...

result = device->CreateBuffer(&matrixBufferDesc, NULL, &m_matrixBuffer);
return true;
}
```

#### 1-3 Blob / ByteCode?
- **Blob**(`ID3DBlob`, `ID3D10Blob`): 크기가 있는 범용 메모리 덩어리.
  - `GetBufferPointer()`로 시작주소, `GetBufferSize()`로 크기를 얻는다.
  -  컴파일 결과물도 담고, 에러 메세지 텍스트(`errorMessage`)도 담는다.
- **ByteCode(DXBC)** 는 HLSL을 `D3DCompile`로 컴파일한 중간 결과.
  GPU가 바로 실행하는 기계어가 아니라 `CreateVertexShader`를 호출할때 driver가 GPU전용 명령어로 다시 변환한다.
- `CreateInputLayout`에 vs바이트 코드를 넘기는 이유 : 검증용
  Layout이 VS의 입력 시그니쳐 (`POSITION`, `COLOR`)와 맞는지 확인

#### 1.4 반드시 매칭!

| C++ 정점 구조체          | InputElementDesc                         | HLSL 입력 구조체                  |
| ------------------- | ---------------------------------------- | ---------------------------- |
| `XMFLOAT3 position` | `POSITION`, `R32G32B32_FLOAT`, offset 0  | `float4 position : POSITION` |
| `XMFLOAT4 color`    | `COLOR`, `R32G32B32A32_FLOAT`, offset 12 | `float4 color : COLOR`       |

> C++는 `XMFLOAT3`, HLSL은 `float4`인 이유 : IA가 빠진 w성분(동차좌표) 을 자동으로 1로 채워준다.
> 그래도 `input.position.w=1.0f`로 명시!


### 2. SetShaderParameters (매 frame/Draw마다)

``` cpp
bool ColorShaderClass::SetShaderParameters(ID3D11DeviceContext* deviceContext, XMMATRIX worldMatrix, XMMATRIX viewMatrix, XMMATRIX projectionMatrix)
{
HRESULT result;
D3D11_MAPPED_SUBRESOURCE mappedResource;
MatrixBufferType* dataPtr;
unsigned int bufferNumber;


//전치 : Shader를 위한 전치 행렬준비 - vs돌리기위한 matrix
worldMatrix = XMMatrixTranspose(worldMatrix);
viewMatrix = XMMatrixTranspose(viewMatrix);
projectionMatrix = XMMatrixTranspose(projectionMatrix);

// CPU가 GPU 버퍼 메모리에 쓸 수 있도록 포인터 받음
result = deviceContext->Map(m_matrixBuffer, 0, D3D11_MAP_WRITE_DISCARD, 0, &mappedResource);
...

dataPtr = (MatrixBufferType*)mappedResource.pData;
dataPtr->world = worldMatrix;
dataPtr->view = viewMatrix;
dataPtr->projection = projectionMatrix;

//반드시 Unmap! GPU가 갱신된 버퍼를 사용할수있도록!
deviceContext->Unmap(m_matrixBuffer, 0);

...
//VS에서 update된 상수 buffer를 최종 set
bufferNumber=0;

// Constant buffer slot(b0)에 바인딩
deviceContext->VSSetConstantBuffers(bufferNumber, 1, &m_matrixBuffer);

}
```

- **Map/Unmap**
	1. CPU쪽 작업이다 (vs가 lock하는게 앙님).
	2. `Map` : CPU가 GPU 리소스 메모리에 쓸 수있는 포인터를 받는다
	3. `Unmap` : 다시 돌려준다
	4. D3D9에서는 `Lock/Unlock`이었고 D3D10이후 `Map/Unmap`으로 바뀌었다
	5. `D3D11_MAP_WRITE_DISCARD` : 이전 내용은 버리고 새로 쓴다.
	   드라이버가 내부적으로 새 메모리를 renaming하기 때문에, GPU가 이전 프레임 데이터를 쓰는 중이라도 CPU가 기다리지 않는다.
	6. 이 방식은 버퍼가 `USAGE_DYNAMIC` + `CPU_ACCESS_WRITE`로 생성 되어있어야 가능


- **Transpose(전치)**의 이유
  1. DirectXMath는 row-major저장, hlsl 기본은 column-major로 읽음
  2. `#pragma pack_matrix(row_major)`또는 `row_major matrix`로 선언하면 전치 없이도 가능

### 3. RenderShader(그리라)

```cpp
void ColorShaderClass::RenderShader(ID3D11DeviceContext* deviceContext, int indexCount)
{
	// Vertex Input Layout Set!
	deviceContext->IASetInputLayout(m_layout);
	
	// Triangle Render할때 쓸 VS, PS를 Set!
	deviceContext->VSSetShader(m_vertexShader, NULL, 0);
	deviceContext->PSSetShader(m_pixelShader, NULL, 0);
	
	// 삼각형 그려라!
	deviceContext->DrawIndexed(indexCount, 0, 0);
}
```
`ColorShaderClass::Render`가 wrapper로써 `SetShaderParameters`->`RenderShader`를 순서대로 호출!

### 4. HLSL (colorShader.hlsl)

``` cpp
//colorShader.hlsl

//SetShaderParameter에서 올린 ConstantBuffer 변수들 받아올수있음
cbuffer MarixBuffer
{
	matrix worldMatrix;
	matrix viewMatrix;
	matrix projectionMatrix;
};


struct VertexInputType
{
	float4 position : POSITION;
	float4 color : COLOR;
};

struct PixelInputType
{
	float4 position : SV_POSITION;
	float4 color : COLOR;
	//float2 tex:TEXCOORD0; //이 쉐이더에서는 안씀!
};

PixelInputType ColorVertexShader(VertexInputType input)
{
	PixelInputType output;
	
	input.position.w = 1.0f;
	
	//vs 행렬 돌리기
	output.position = mul(input.position, worldMatrix);
	output.position = mul(output.position, viewMatrix);
	output.position = mul(output.position, projectionMatrix);
	
	output.color = input.color;
	
	return output;
}

//기본 input color 받기
float4 ColorPixelShader(PixelInputType input) : SV_TARGET
{
	return input.color;
}
```
Semantic은 연결 이름표
- float4가 hlsl에서 사용할수있고 읽을 수있다
- `POSITION`, `COLOR`, `SV_POSITION`, `TEXCOORD0` 같은 Semantic은 IA->VS->PS단계에서 같은 이름끼리 연결하는 **매칭 규약**
- Data를 나르는(convey)것은 Semantic이 아닌 Buffer.
- `SV_`는 SystemValue, pipeline이 특별한 의미를 부여하는값(`SV_POSITION`, `SV_TARGET` 등).

###### VS / PS Flow
**VS**
1. GPU에서 VS를 부르고, vertex buffer에서 data processing한다.
2. vertex buffer의 개별 Vertex 마다 한번씩 실행된다/
3. vertex buffer 데이터 포맷과 vs의 input은 일치해야 한다
4. vs의 output은 Rasterizer를 거쳐 pixelshader로 전달된다.
	- `SV_POSITION`은 Clip 공간 좌표 → Rasterizer가 NDC/Viewport 변환
	-  나머지 출력(Color 등)은 보간(**interpolation**)된다.

→ 자동적으로 **Rasterizer**가 NDC/Viewport변환(View frustum)은 고정 기능이라 자동으로 한다!, 단 viewport크기는 `RSSetViewports`로 설정!

**PS**
1. 화면에 렌더링 된 Polygon 위의 매 pixel마다 실행된(그린)다
2. PS는 VS output 자체가 아니라 **Rasterizer**가 보간한 값을 받는다

### 5. Semantic vs register

|     | Semantic                                        | register                      |
| --- | ----------------------------------------------- | ----------------------------- |
| Ex  | `POSITION`, `COLOR`, `SV_POSITION`, `TEXCOORD0` | `b0`, `t0`, `s0`, `u0`        |
| 용도  | **스테이지 간 데이터 연결**  <br>(IA→VS→PS 입출력 매칭)        | **CPU가 바인딩한 리소스를 셰이더 변수에 연결** |
| 대상  | 정점/픽셀 입출력 변수                                    | 상수 버퍼, 텍스처, 샘플러, UAV          |
#### 5.1 register 접두사

|접두사|의미|C++ 바인딩 함수|
|---|---|---|
|`b#`|상수 버퍼|`VSSetConstantBuffers(slot, ...)`|
|`t#`|텍스처 / SRV|`PSSetShaderResources(slot, ...)`|
|`s#`|샘플러|`PSSetSamplers(slot, ...)`|
|`u#`|UAV (컴퓨트 등)|`CSSetUnorderedAccessViews`|


```cpp
cbuffer MatrixBuffer : register(b0) { ... }
Texture2D    shaderTexture : register(t0);
SamplerState sampleType    : register(s0);
```

- `VSSetConstantBuffers(bufferNumber, ...)`의 `bufferNumber`가 **b 슬롯 번호**다.
- register를 생략하면 컴파일러가 선언 순서대로 0번부터 자동 배정한다.
  버퍼가 여러 개가 되면 명시하는 게 안전하다.
- 텍스처를 쓰게 되면 `TEXCOORD0`(semantic, 정점 입력)과 `t0`/`s0`(register, 리소스)을 같이 쓴다.

### 6. 파이프라인 단계와 코드 매핑

|파이프라인 단계|관련 코드|
|---|---|
|IA|`CreateInputLayout`, `IASetInputLayout`, vertex/index buffer|
|VS|`CreateVertexShader`, `VSSetShader`, `VSSetConstantBuffers`|
|Rasterizer|(고정 기능) 클립/NDC/뷰포트 변환, 보간|
|PS|`CreatePixelShader`, `PSSetShader`|
|OM|렌더 타겟 / 깊이 스텐실 (`SV_TARGET`으로 출력)|
Rasterizer와 OM설정은 `D3DClass`초기화에서 이루어 짐.

### 7. 추가 메모

- **상수 버퍼 16바이트 정렬**: cbuffer 크기는 16바이트 배수여야 한다. `float3` 뒤에 `float`가 안 오면 패딩이 필요하다 (라이트 방향 등을 넣을 때 바로 부딪힘).
- **해제(Shutdown)**: `m_matrixBuffer`, `m_layout`, `m_pixelShader`, `m_vertexShader` 순으로 Release. 컴파일 후 Blob Release도 잊지 말 것.
- **에러 처리**: `errorMessage` Blob을 `OutputShaderErrorMessage` 등으로 출력하는 부분이 셰이더 디버깅의 핵심.
- DX11은 raw하게 Window/Device에 붙어서 하기 때문에 구조체가 번거롭지만, 그만큼 메모리에 정확히 무엇을 꽂아 넣는지 이해하기 좋다.
