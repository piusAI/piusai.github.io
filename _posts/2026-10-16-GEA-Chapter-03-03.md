**ALU** : 단항, 이항 수리연산 수행 
- 항상 "CPU는 강력한 계산기, GPU는 단순한 계산기들이 동시에 연산한다"할때 의 연산과정을 처리하는 부분 ALU임!

### ALU의 시각화
- CPU (복잡한 연산에 강함)
- GPU (단순 반복 연산에 강함):  단순한 ALU 수천개가 동시에 일어남(NVIDIA GPU : 수천~만개 이상)
- AU(Arithmetic Unit), LU(Logic Unit)으로 나뉜다

**VPU**- 하나의 수리연산자가 여러 입력 동시에 수행(**SIMD**)

``` cpp
// UE FMatrix : SIMD 최적화
FMatrix Matrix1, Matrix2;
FMatrix Result = Matrix1*Matrix2; // SIMD로 한번에 4개씩 계산

// DirectX
XMMATRIX mat1, mat2;
XMMATRIX result = XMMatrixMultiply(mat1, mat2); // SSE, AVX사용
```

- 최근 FPU는 사라지고있다! Scalar float도 VPU에서 처리한다.
  -> 보다 큰 cache용량, 더 복잡한 비순차 실행로직등 구현하는데 활용

 **SIMD** :  
- 한 명령어로 여러 데이터를 동시에 처리  
- 4x4 행렬은 16개의 float ->SIMD로 4개씩 묶어서 처리하면 4배 빠르겠다
- SSE, AVX같은 명령어 세트 사용!

##### **Register**:  
- 계산 + 저장을 자유롭게 하는 저장소
- 이로써 ALU, FPU의 성능 극대화  
- 데이터 읽기/쓰기 속도가 가장 빠름, 이후 L1, L2, L3... cache 순  
- Acuumulator : ALU가 비트 처리후 마스킹 시프팅으로 레지스터에 축적했음.

**구체적인 레지스터**들 (x64 기준)
```
┌─────────────────────────────────────┐
│     범용 레지스터 (16개)               │
│      - 계산 + 저장 자유롭게             │
├─────────────────────────────────────┤
│       RAX  ◄─ 주로 계산 결과, 리턴 값   │
│       RBX  ◄─ 베이스 주소             │
│       RCX  ◄─ 카운터 (루프)           │
│       RDX  ◄─ 데이터                 │
│       RSI  ◄─ 소스 인덱스             │
│       RDI  ◄─ 목적지 인덱스           │
│       R8~R15 ◄─ 추가 범용            │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│       특수 레지스터(SPR, 포인터 전용!)    │
│        - 특정 용도로만 사용             │
├─────────────────────────────────────┤
│  RIP  ◄─ 명령어 포인터 (다음 실행할 명령어 주소)
│  RSP  ◄─ 스택 포인터 (스택 최상단 주소) ★

┌─────────────────────────────────────┐
│      제어/상태 레지스터                 │
├─────────────────────────────────────┤

└─────────────────────────────────────┘
```



- CPU는 과거에 **일처리(연산)**만 했지만 최근의 CPU내부의 레지스터, L1, L2cache가 붙으면서 **저장소도 갖고있음**

  2. 스택 포인터, RSP(Stack Pointer)
  3. 베이스 포인터 (Base Pointer)

#### 3.4.5 메모리

- 전원이 공급되는 동안만 데이터를 저장함
- SRAM, DRAM으로 나뉜다. (DRAM의 내부는 '격자'구조)
- 주소는 결합된것: 가상 주소 → 물리 주소 → (Channel, Bank, Row, Column)
- 가상 주소에서는 연속적이지만 물리 주소로 본다면 Random하게 들어감
- Ram은 논리적으로는 연속 주소처럼 보이지만 물리적으로는 격자 구조라 아래로 쌓이지 않는다.
- Capacitor, 데이터(0 or 1)을 전하의 형태로 저장
- Transistor, 스위치 증폭 소자, 캐패시터에 접근하는 통로 열고 닫는 스위치

이 구조 덕분에 DRAM은 셀이 작고 가격저렴, 리프레시 필요

#### 3.4.7 기계어와 어셈블리어

- CPU 입장으로 프로그램은 코드 한줄 한줄의 명령어의 stream!
- **ISA(Instruction Set Architecture)** : 명령어 집합 아키텍쳐
- **ABI(Application Binary Interface)** : 컴파일된 binary 수준에서 프로그램끼리, Os-프로그램이 어떻게 상호작용 할지 정한 규약

| |ISA|ABI|
|---|---|---|
|수준|CPU가 실행하는 명령어|바이너리 간 호환 규약|
|정하는 것|"어떤 명령이 있는가"|"그 명령을 어떻게 조합해 함수 호출·데이터 배치를 하는가"|
|호환의 의미|같은 CPU 명령 실행 가능|따로 컴파일된 코드끼리 링크·호출 가능|

- 명령어에 따라서 레지스터 이름 / 숫자 리터럴로 받는다
##### 3.4.7.2 기계어
**기계어 명령어의 세 부분**:  
1. **명령 코드(opcode)** : CPU에 어떤 동작을 수행할 것인지 알려줌  (덧셈, 로드, 분기 등)
2. **피연산자(operand)** : 명령어의 입출력 지정  (피연산자값, 레지스터 번호, 주소 등 실제 정보)
3. **옵션 필드** : 주소 모드 / 기타 플래그 지정  
   - **주소 지정 방식**(Addressing mode | AM ) : 명령어의 피연산자(operand)가 실제로 어디에 있는지, 어떻게 그 위치를 계산해서 찾아가지는지를 정한 규칙 (operend 필드를 어떻게 해석할지 알려주는 비트)

> | Opcode | AM | Operand |
> 명령어 인코딩하는 가상의 방식

**주소 지정방식(AM) 비교**:  

| AM 방식                     | 어셈블리 (x86)          | 대응하는 C 코드                   | 동작 설명                                |
| ------------------------- | ------------------- | --------------------------- | ------------------------------------ |
| **즉시**                    | `mov eax, 5`        | `int a = 5;`                | 값 5가 명령어에 들어 있어 eax에 바로 넣음           |
| **레지스터**                  | `mov eax, ebx`      | `a = b;` (둘 다 레지스터에 있을 때)   | ebx의 값을 eax로 복사                      |
| **직접**                    | `mov eax, [0x1000]` | `a = g;` (전역변수 g가 0x1000번지) | 메모리 0x1000번지의 값을 eax로 읽음             |
| **레지스터 간접**<br>(포인터 역참조)  | `mov eax, [ebx]`    | `int y = *p;`               | ebx에 든 주소를 따라가서 그 위치의 값을 eax로 읽음     |
| **레지스터 간접**   (저장)        | `mov [ebx], eax`    | `*p = y;`                   | eax의 값을 ebx가 가리키는 주소에 저장             |
| **상대 / 변위**   <br>(배열 접근) | `mov eax, [ebx+12]` | `int y = a[3];`             | 배열 시작 주소(ebx) + 12바이트(3×4) 위치의 값을 읽음 |
 

**명령어 워드(Instrurction word)**:  

```
//16비트 명령어 워드
[4비트 Opcode][4비트 Reg1][4비트 Reg2][4비트 Reg3]

0001 0010 0011 0100
// 0001 Opcode : ADD
// 0010 Reg1 : R2(목적지)
// 0011 Reg2 : R3(첫번째 소스)
// 0100 Reg3 : R4(두번째 소스)
// R2 = R3 + R4
```

**VLIW (Very Long Instruction Word)** : opcode 와 Operand 모두 포함 해야해서 명령어 워드 1개에 넣어서 병렬로 실행할 수 있음. 매우 커질 수있다.
##### 3.4.7.3 어셈블리 언어

ASM은 차례로 나열된 명령어로 이루어짐

``` cpp
//C++ 조건문 코드
 int x = 10;
 int result;
 
 if(x>5){
 	result = 1;
 }
 else{
 	result = 0;
}

// x86-64 ASM
	movl    $10, %eax       # eax = 10 (x)
    cmpl    $5, %eax        # x와 5를 비교
    jle     .else_branch    # x <= 5이면 else로 점프
    
.if_branch:
    movl    $1, %ebx        # result = 1
    jmp     .end_if         # if 종료, else 건너뛰기
    
.else_branch:
    movl    $0, %ebx        # result = 0
    
.end_if:
    # 계속 실행...
```

- 1줄당 1개의 명령어

### Chapter3.5 메모리 구조

CPU의 레지스터도 일종의 메모리지만, 주소로 접근치 않고, 어셈블리 언어의 이름을 통해 접근함!

  
#### 3.5.1 메모리 매핑

- 주소 공간이 메모리 장치에 매핑 됨 : 물리적 메모리 장치가 컴퓨터의 특정 주소 공간의 일부로 배정

#### SRAM vs DRAM

01 셀 구현 기술 → ' 작업시 필요한 아날로그 작업의 양'

  

- **SRAM**

   레지스터, L1, L2, L3, cache

- 보통 6T( 6 transistor) flipflop
- 전원이 있는한 상태 유지

  

- **DRAM**

   메인 메모리

1. Row 활성화(wordline ON)

2. 캐패시터 전하를 비트라인으로 공유

3. 센스 엠프가 미세한 전압 차이를 증폭

4. 읽는 순간 값이 파괴됨 : 다시 써야함(restore)

5. Row 닫기(precharge)

- 물리적으로 단계가 많음
- 1T + 1C(트랜지스터 + 캐패시터)
- 전하 유무로 0/1 표현

: SRAM이 DRAM보다 접근지연이 낮다. 더 많은 트랜지스터를 사용하고 복잡해서.

🙅🏼 다르면 Cache Miss : **주소가 포함**된 캐시 라인 전체 (2ⁿ byte) 를 가져옴

  

> Cache는 계속 확인하고 계속 바꿔 끼우면서 Cache Miss낮추고 Hit를 높히는데,  
> SoftWare에서 접근 패턴(자료구조)을 잘 짠다면 미스 자체가 많이 줄어들겠다

> Q) Miss인듯 Miss아닌 Hit같은너  
> A를 처음 Cache한다음 B를 활용하려 ( Miss난 A를 Cache) 덮어씀, 그 이후에 다시 A를 쓰기위해서 B에 덮어쓴다면?  
>   
> A) 이것이 자료구조를 잘 짠다는 의미  
> 함께 자주 쓰이는 데이터를 **시공간적으로 가깝게, 캐시에 존재 가능**하게

  

// ❌ 자료구조가 나쁜경우

struct A { int x[64]; };
struct B { int y[64]; };

A a;
B b;

for (int i =0 ; i < 64 ; i++){
	sum += a.x[i];
    sum += b.y[i];
}

// 이렇게 a.x와 b.y가 같은 cache Index에 매핑된다면
// 매 반복마다

a miss → b miss → a miss → b miss

✅ 자료구조를 바꾼 경우 SoA

struct AB{
	int x;
    int y;
};
    
AB arr[64];

for (int i = 0 ; i < 64 ; i ++ ) {
	sum += arr[i].x;
    sum += arr[i].y;
}

// 👉 같은 캐시라인에 존재하기에 히트율 폭증!

이렇게 SoA가 AoS보다 압도적으로 좋을때가 많다.

  

- 직접 매핑 << 2중 집합 연관(set Associative cache) << 4중 집합 연관

- CPU replacement Policy에 따라 메모리 Cache를 정리함.

  

- 고성능 코드를 위해서 I$(Instruction Cache), D$(data Cache) 둘다 캐시한다.
