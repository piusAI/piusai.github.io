#### 02 컴파일러, 링커, IDE

- 소스파일 : translation Unit이라고 부르기도 함  
- 컴파일러 자체는 헤더파일이 있는지 모르기에 전처리기에 #include 구문을 넣어서 헤더 파일의 내용으로 교체!

> Translation unit 1개 -[Compile]--> Object 파일(.obj)에 저장됨

- Library : Obj파일 여러 개를 묶은 것 
- 목적파일의 특징 : 메모리 주소 미결정, 링크되지 않음

> Obj 파일 + Library -(Linker)-> execute 파일 : 링킹한다 //이때 메모리 주소값, 외부 참조 확정(resolve)

- 메모리 주소 확정 시점

실행파일의 기계어 코드가 아닌, 링커에서 **상대주소**를 결정한다.  
모든 기계어, 데이터를 가리키는 메모리 주소는 절대적으로 고정된 주소가 아니라, 기준값에 더해질 상대적인 값이다.  
**절대 메모리 주소**는 **실행 파일**이 실행되기 직전에 메모리에 로드될 때 결정된다!  
링커마저도 상대 주소를 결정함

  

- DLL Dynamic Link Library, 동적 링크 라이브러리
  (정적) Object - (동적) 실행 파일의 중간 형태  
+ 호출할 수 있는 함수(Library) + OS가 따로 로드한다(Exe)
  DLL은 실행파일과 관계없이 DLL만 교체할 수 있다는 점에서 유용

- MSVC : 마소 전용 최적화  
- Clang : LLVM 기반 컴파일러 

- LLVM : 컴파일러 프레임 웤

> 소스코드  
>   ↓  
> FrontEnd (Clang)  
>   ↓  
> LLVM IR  
>   ↓  
> Optimizer  
>   ↓  
> BackEnd  
>   ↓  
> 기계어

  
LLVM 컴파일러 프레임웍


| 항목   | MSVC    | Clang + LLVM |
| ---- | ------- | ------------ |
| 구조   | 단일 컴파일러 | 모듈형          |
| IR   | 비공개     | 공개           |
| 최적화  | MS 내부   | LLVM Pass    |
| 확장성  | 낮음      | 매우 높음        |
| 연구/툴 | 제한적     | 풍부           |
MSVC vs Clang/LLVM

  

SIMD : Single Instruction Multiple Data

하나의 명령어로 여러 개의 데이터를 한 번에 처리하는 병렬 방식의 기법

- 2개 이상의 빌드 설정 사용 : Relase Build, Debug Build를 따로 해서 다룬다
- Macro설정 : Source Code에 넣나, VS Build 설정에 넣나 같다

Houdini에서의 $HIP, $OS도 같은 매크로( 조금 더 명확하게라면 전역변수)

``` cpp
#define DEBUG_MODE 1
#if DEBUG_MODE
	Log();

#endif

//source code에 직접 쓰는 경우

/DDEBUG_MODE = 1
//VS build설정에 넣는경우
```
  
``` cpp
#if UE_BUILD_DEBUG
#if UE_BUILD_DEVELOPMENT
#if UE_BUILD_SHIPPING

#if WITH_EDIOR

// _DEBUG(Debug빌드) / NDBUG(Relase계열) 를 쓰지는 않음
// UnrealBuildTool에서 알아서 정의를 해준다
```
  
| 항목     | Debug    | Release |
| ------ | -------- | ------- |
| 최적화    | ❌ 거의 안 함 | ✅ 강하게 함 |
| 인라인    | ❌ 제한적    | ✅ 적극적   |
| 디버그 심볼 | ✅ 많음     | ❌ 최소    |
| 어서트    | ✅ 활성     | ❌ 제거    |
| 성능     | 느림       | 빠름      |
Debug Build vs Relase Build

  

- 로컬 최적화 vs 글로벌 최적화

로컬 최적화 : 하나의 Translation Unit(. cpp) 안에서만, 하나의 기본 블록 내에서 만의 최적화  
글로벌 최적화: 컴파일러보다 링커가 수행(Translation Unit을 넘나들어야 해서)

| 항목    | 로컬 최적화  | 글로벌(LTO) |
| ----- | ------- | -------- |
| 범위    | 함수 / 파일 | 전체 프로그램  |
| 시점    | 컴파일     | 링크       |
| 정보    | 제한적     | 전체       |
| 인라인   | 제한적     | 파일 간 가능  |
| 빌드 속도 | 빠름      | 느림       |
| 성능    | 중간      | 최고       |

LTO : Linker-Time Optimization  
링크 타임에 수행되는 전역 최적화

> -O0 // 최적화 하지 않은 상태
> -O3 //모든 최적화를 켠 상태

