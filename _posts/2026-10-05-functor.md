Functor(함수 객체)는 `operator()`를 오버로딩해서, 함수처럼 호출할 수 있는 객체이다!
[함수 포인터](https://piusai.github.io/cpp/2026-09-30-funcpointer)는 **동작**만 담을 수있다. 함수처럼 호출되는 **객체**를 쓰면 무엇이 가능해지는 걸까?

> 함수처럼 보이지만 사실 `operator()`로 오버로딩 한 것이다.

**함수 포인터의 한계**:
1. 시그니처가 맞지 않다면 사용 불가
2. 상태를 가질 수 없다 (데이터 바인딩 불가)

### Functor의 기본
`operator()`를 오버로딩 하면 객체를 함수 포인터처럼 호출 할 수있다. 
여기에 멤버 변수까지 두면 **상태**까지 가질 수가 있다
``` cpp
class Functor
{
public:
	// overloading funcptr처럼보이게
	void operator()() { 
		cout << "Functor Test : " << endl;
		cout << _value << endl;
	}
	//동작 - member 함수
	void AddValue(int value) { _value += value; }

public:
	//상태 - member 변수
	int _value = 0;
};

int main()
{
	Functor func;      // 함수 객체
	func._value = 10;  //상태 저장
	func();            // 함수처럼 호출
}
```


```cpp
struct Compare
{
	bool operator()(int a, int b) const
	{
		return a > b;
	}
};

priority_queue<int, vector<int>, Compare> pq; //최소 heap
```

- 비교 함수는 상태를 바꾸지 않으므로 `const`를 붙이는게 관례
- `const`는 `this` 객체를 `const`로 만든다 → [const에 관한 글](https://piusai.github.io/c++/2026/08/27/const.html)
- 비교 함수는 "a가 b보다 우선순위가 낮은가?"를 의미해서, `>`를 쓰면 작은 값이 먼저 나오니 최소 heap이 된다.

### Functor와 Template의 조합

- **함수 포인터 타입**을 인위적으로 지정하지 말기!
- 어떤 `T` 에 객체 넣어줄테니 그 객체에 `()`문법을 실행해라

``` cpp
struct AddStruct
{
	int operator()(int a, int b)
	{
		return a + b;
	}
};

// using FuncPtr = int(*)(int, int); 이제 시그니쳐 맞출 필요 없다!

template <typename T>
int DoSth(int a, int b, T funcptr)
{
	return funcptr(a, b);
}

int main()
{
	AddStruct as;
	cout<< DoSth(20, 40, as)<<endl;
}
```
`T`는 `()`로 호출만 가능하면 되니까, 일반함수, functor 모두 받을 수 있다.


#### 클래스 전체를 Template으로
``` cpp
template<typename T>
struct AddStruct {
	T operator()(T a, T b) { return a + b; }
};

template<typename T, typename T1>
T Dosth(T a, T b, T1 funcptr)
{
	return funcptr(a, b);
}

int main()
{
	AddStruct<float> addstruct;
	cout<<Dosth(20.2f, 40.0f, addstruct)<<endl;
}
```

한번 더 나아가봐서 타이추론까지 맞춰봤다.



##### Q) 꼭, 변수를 만들어야하나?
A. 아니다. **임시객체**를 바로 넘기면 된다.
``` cpp
	cout<<Dosth(20.2f, 40.0f, AddStruct<float>())<<endl;
```
기본 생성자로 객체를 만들어 바로 넘기는 방식이다.

그래도 변수로 만들어야 하는 이유 :
- 같은 functor를 여러번 재 사용할때
- 상태 유지하거나 나중에 확인해야 할때

##### `operator()`만 Template으로
class 전체가 아니라 `operator()`만 템플릿으로 만들면 `AddStruct<float>`과 같이 타입을 적을 필요 없다.
``` cpp
struct AddStruct {
	template<typename T>
	T operator()(T a, T b) { return a + b; }
};

template<typename T, typename T1>
T DoSth(T a, T b, T1 funcptr)
{
	return funcptr(a, b);
}

int main()
{
	AddStruct addstruct;
	cout<<DoSth(20.2f, 40.0f, AddStruct())<<endl;
}
```
> 주의 : `DoSth(20, 40, 40.5f, ..)`처럼 두 인자의 타입이 다르면 `T`가 충돌해서 컴파일 에러를 뱉는다!


### `priority_queue`에서의 greater<>가 말하는 바!
``` cpp
template <typename T>
struct Greater {
	bool operator()(const T& _Left, const T& _Right) const
	{
		return _Left > _Right;
	}
};
```
이 functor를 뜻하고 있었다!!

### Functor의 장점(vs Func Pointer)

1. 상태를 가질 수있다 - DataBinding 가능
2. Template과 TeamPlay가 가능하다 (범용적 사용 가능)
3. 타입 자체가 호출할 함수를 결정하므로, 컴파일러가 **인라인 최적화**하기가 쉽다
   함수 포인터는 런타임에 결정되어 어려움.


> Functor는 한마디로 함수포인터 + (상태 , template)이다.

참고 : 람다는 내부적으로 compiler가 만들어주는 이름없는 functor이고, 캡처가 곧 멤버 변수(상태)이다.
